# analysis — 웹툰 연출 분석 파이프라인

DB 시트 「작업 방법」 시트의 단계와 같은 순서입니다.

| 단계 | 스크립트 | 하는 일 |
|---|---|---|
| 1 수집 | `fetch.sh 작품ID 화 출력폴더` | 네이버웹툰 회차 이미지를 받아 `strip.png`로 이어 붙임 |
| 2 분할 | `seg2.py` (`segment()`) | 여백 행 기준 블록 분할 + 40px 미만 조각 합치기 |
| 2 보기 | `bsheet.py strip seg.json 시작 끝 출력.jpg` | 블록 모음 이미지 (블록 번호와 높이 표시) |
| 3 판정 | (사람) `gmE_notes.txt`, `gmE_scenes.txt` 작성 | 형식은 아래 |
| 4~5 계산 | `WORK_CODE=GM WORK_TITLE=작품명 pipe.py E glist|write` | 묶음 목록 확인 → 컷표·5컷 리듬·장면·컬러 띠 행 생성 (`gmE_write.json`) |
| 6 검사 | `check_pre.py gmE_write.json` | 코드표 값, 컷 번호 연속, 묶음 겹침 검사 |
| 7 쓰기 | `mkxlsx.py E` | 시트 가져오기용 엑셀 파일 생성 |
| 8 검사 | `check_post.py 시작행 읽기결과.json...` | 시트를 다시 읽은 결과와 한 칸씩 대조 |
| 이두나! | `dn_cutsheet.py`, `dn_align.py` | 영문판 좌표를 네이버 원본에 맞추는 데 쓴 스크립트 |

## 판정 노트 형식 (`gmE_notes.txt`)
`블록범위|유형|샷|앵글|역할|감정|강도|세부감정|블록내컷|말풍선수|그림밀도|내용|장면키`
- 블록범위: `12` 또는 `13-17` (여러 블록을 한 컷으로 합침)
- 크레딧 등 제외: `128-134|X`

## 장면 파일 (`gmE_scenes.txt`)
`S01|장면 이름|시작 상태|끝 상태|전환점 컷 번호`

## 연출명 파일 (`{코드}E_annx.txt`)
`G01|연출명|리듬 한 줄|연출 의도|VNG|주된 컷 전환` (묶음 번호는 `pipe.py glist` 기준)

## 분할 정확도 (녹빛자정의 연인 1~7화 수작업 결과 기준)
- 경계 일치 98.7%, 블록/최종 컷 1.28 (기존 1.31)

## 리듬 분류 (`taxonomy.py`)
5컷 리듬 표를 거리 흐름·템포·서사 형태·정보 흐름·색 흐름·감정 곡선·연출 목적 코드로 바꿉니다. 정의는 `../docs/codebook.md`.

## 데이터 취급
원본 웹툰 이미지와 작품 내용(컷 묘사·대사)이 담긴 작업 폴더는 `.gitignore`에서 제외합니다. 공개 범위를 확인한 컷 분석 CSV는 [cut-context](./cut-context/)에 있습니다. 이 자료는 4개 작품의 3,732개 블록을 다루며, 이 중 2,935개 블록에 상세 서술이 수록되어 있습니다.

- `narrative-*.csv`는 작품별 컷 서술과 앞뒤 흐름을 담습니다.
- `detail/`은 구도, 여백, 명암, 효과와 검수 정보를 담습니다.
