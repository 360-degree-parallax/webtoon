# 러프 툴 기획 — 선택 최소화, 연산 적용, 한 페이지

작업 방법(프롬프트 → 컨텍스트 → 도구 → 워크플로) 순서로 정리합니다. 값과 판정 기준은 모두 [코드표](codebook.md)를 따릅니다.

## 1. 목표 (프롬프트)
장면 글만 넣으면 연출 DB(244묶음)를 근거로 러프 한 안이 바로 나온다.
- 사람이 반드시 할 일: **장면 글 쓰기** 하나.
- 사람이 할 수 있는 일(선택): 다른 안 보기, 컷 값 하나 고정하기, 참고 그림 적용.
- 모든 판정에는 이유가 붙는다. 사람이 이유를 보고 틀린 것만 고친다.

## 2. 사람이 정하던 것 → 연산으로 바꾼 것 (컨텍스트)
| 예전 선택 | 지금 계산 | 근거 (코드표) |
|---|---|---|
| 카메라 거리 | 서사 형태·연출 목적에서 목표 거리 흐름 유도 | 커버리지 원경→근경, Block 공간 대비 |
| 속도 | 평균 강도·느낌표 밀도·문장 길이 → 빠름/보통/느림 | 웹툰 스크롤 페이싱 |
| 터지는 순간 | 컷별 강도의 최댓값 위치·개수 → 서사 형태 | Cohn VNG의 P 위치 |
| 노리는 효과 | 인물 교대·소품·물음표·전환어 등 규칙 → 연출 목적 | 연출명 기본값 규칙 |
| 컷별 샷·앵글·길이 | 패턴 컷 + 역할·감정·강도 보정 | 컷표 분포, 여백 관습 |

## 3. 연산 단계 (도구)
`rough/engine.js` 하나에 모아 브라우저와 Node 테스트가 같은 코드를 쓴다.

1. **파싱**: `인물 | 행동 "대사"` → 인물, 행동, 대사, 문장부호.
2. **감정·강도** (컷표 감정 14종, 강도 0~3): 낱말 사전(감정별 표정·몸짓·의성어·대사 표현)으로 감정과 기본 강도를 찾는다. 여러 감정이 맞으면 강도가 높은 쪽, 같으면 더 긴(구체적인) 낱말. `!`와 강한 표현(갑자기·펑펑·버럭 등) +1, 약한 표현(살짝·애써 등) −1(감정 낱말이 있으면 최소 1), 물음표만 있으면 의아.
3. **역할** (설정/전개/공개/반응/전환): 전환어 → 전환, 첫 컷의 장소·등장 → 설정, 반응 동사 → 반응, 드러남·강한 대사 → 공개, 나머지 전개.
4. **VNG**: 강도 최댓값(2 이상) 컷이 P, 앞쪽 설정·전환이 E, P 앞 첫 컷 I, 사이 Pr, P 뒤 R.
5. **묶음 지표**: 서사 형태(P 위치·개수), 감정 곡선(처음·최대·최소·끝), 주된 컷 전환(McCloud: 인물이 바뀌면 주체, 같은 인물이면 동작, 감정만 바뀌면 순간, 인물 없으면 양상, 전환어면 장면), 연출 목적(순서 규칙), 템포, 목표 거리 흐름.
6. **패턴 검색**: 244묶음과 가중 유사도
   서사 형태 3 · 감정 곡선 2 · 연출 목적 2 · VNG 순서 2 · 컷 수 1.5 · 컷 전환 1 · 템포 1 · 거리 1 · 감정 겹침 1 → 일치도 %. 1위를 쓰고 나머지는 '다른 안'.
7. **컷 배치**: 장면 P와 패턴 P를 맞춘 뒤 앞뒤를 비례로 대응.
   - 샷: 패턴 컷 샷 → 설정 역할은 넓게, 정점의 강한 감정은 클로즈업 이상, 핵심 소품은 디테일.
   - 앵글: 패턴에 확인된 앵글이 있으면 그대로, 없으면 감정으로(결의·분노 → 로우, 쓸쓸·당황 → 하이, 장소 소개 → 하이, 그 외 아이레벨).
   - 길이: 패턴 길이 × 강도 보정, 정점은 최소 1.1, 템포 보정.
   - 여백: 패턴 여백 × 템포, 정점 뒤 ×1.6, 장면 전환 앞 ×1.8.
8. **참고 그림 추천**: 컷마다 컬러 러프·창작 클로즈업 중 샷·앵글이 가장 가까운 한 장을 붙인다(누르면 적용).

묶음은 코드표대로 5컷 기준, 3~7컷 허용, 2컷 이하 꼬리는 앞 묶음에 합친다.

## 4. 화면 (한 페이지)
- 왼쪽: 장면 글 → "이렇게 읽었어요"(한 문장 요약 + 계산값 + 고른 패턴과 일치도) → 컷 표(구조·감정·샷·앵글·길이·참고, 각 칸에 이유).
- 오른쪽: 고정 미리보기와 떠 있는 툴바(다른 안 ‹ n/12 ›, 저장).
- 칸을 누르면 값 목록이 열리고, 고른 값은 고정(점 표시)된다. '자동'을 고르면 계산값으로 돌아간다.
- 글을 고치면 0.35초 뒤 전체를 다시 계산한다. 고정값은 같은 문장의 컷에만 남는다.

## 5. 검증 (워크플로)
- `node rough/test_engine.js`: 손으로 판정한 예시 장면들의 서사 형태·연출 목적·P 위치와 엔진 결과를 비교해 일치율을 출력한다.
- 같은 테스트에서 모든 패턴에 대해 검색이 오류 없이 돌고 컷 배치가 범위 안(길이 0.45~2.4, 여백 0.08~1.2)인지 확인한다.
- 사전·규칙을 고칠 때마다 이 테스트를 다시 돌린다. 틀린 사례는 테스트에 추가한다.

## 6. 참고 이미지 (캐릭터·장면)
미드저니의 캐릭터/스타일 참고처럼, 사용자가 이미지를 첨부하면 연산에 쓴다. 이미지는 브라우저(IndexedDB)에만 저장하고 밖으로 보내지 않는다.
- **캐릭터**: 장면 글의 `인물` 이름마다 칸이 자동으로 생긴다. 첨부하면 그 이름의 모든 컷에 연결된다.
- **장면**: 여러 장 가능. 장면 이름이 묶음 글에 나오면 그 묶음에, 아니면 묶음 순서대로 돌아가며 쓴다.
- **연산**
  - 팔레트: 48px로 줄여 4비트로 색을 묶고, 많이 쓰인 색 중 서로 다른 5색. 캐릭터 대표색은 채도가 가장 높은 색.
  - 밑그림: 설정·전경 컷은 장면 이미지(38%), 전신·중경·효과 배경은 장면 이미지(22%), 클로즈업은 그 인물 이미지(32%). 흑백으로 깔고 인물 선은 투명하게. 툴바에서 끌 수 있다.
  - 이름표: 인물이 있는 컷에 대표색 이름표.
  - 프롬프트: 컷마다 샷·앵글·감정(강도)·행동·장면 팔레트를 영어로 풀고 `--oref`(캐릭터) `--sref`(장면) `--ar`(컷 비율)를 붙인다. 이미지 링크 자리는 사용자가 채운다.
- 실제 이미지 생성은 외부 생성 API가 필요해 이번 범위에서 뺀다.

## 7. 인물 설정과 줄글 입력
- **인물 칸** (컷 배치 맨 위): 이름, 다른 호칭(쉼표), 체형(여자/남자), 외형. 브라우저에 저장.
  - 이름·호칭: 줄글에서 인물을 찾는 기준. 비어 있으면 조사가 붙어 2번 이상 나오는 이름을 추정하고 "장면에서 찾은 이름"으로 제안한다.
  - 외형: 프롬프트의 `character "이름" (외형)`에 들어간다.
  - 체형: 3D 시안 배역(VRoid 여자/남자 기본 체형)에 그대로 쓰인다.
- **줄글 → 컷** (`engine.js` `parse`): 줄의 절반 이상에 `|`가 있으면 한 줄 한 컷 형식, 아니면 줄글로 본다.
  1. 문장 나누기: 마침표·물음표·느낌표·말줄임표. 따옴표 안의 문장부호는 무시하고, `"…" 하고/라고/하며`처럼 이어지면 한 문장.
  2. 인물: 이름 + 주격 조사(은·는·이·가·도·께서)가 가장 먼저 나오는 인물. 없으면 `이름의 얼굴`처럼 소유격 인물(손목·손·팔·어깨를 잡는 경우 제외).
  3. 컷: 첫머리 배경 묘사는 설정 컷 하나로, 행동 문장은 한 컷씩, 따옴표만 있는 문장은 앞 컷의 대사로 붙인다.
- **@멘션**: `@이름`으로 부르면 그 인물로 확정한다. 조사가 붙어도(`@준이`, `@에드가는`) 인물 칸의 이름을 긴 것부터 맞추고, 없으면 조사를 떼어 이름으로 본다. 인물 칸에 없는 @이름도 인물로 쓰고 추가 버튼으로 제안한다. 장면 칸에서 `@`를 치면 인물 목록 자동완성. 컷 표·프롬프트에는 @를 빼고 보여준다.
- 감정 사전의 분위기 단서(발소리·침묵·정적 등)는 강도 1로 낮춰 인물 감정 낱말이 우선하게 했다.
- 검증: `test_engine.js`의 줄글 예시(6컷, 인물 순서, 대사 붙이기, 감정)를 인물 목록이 있을 때와 없을 때 모두 확인.

## 8. 컷별 입력 양식
장면은 컷마다 한 칸에 적는다(↑↓로 순서, ×로 삭제, Ctrl/⌘+Enter로 아래에 새 컷).
| 줄 | 뜻 | 쓰임 |
|---|---|---|
| `[식자내용]` | 식자(내레이션) | 러프·3D에 글상자, 감정 판정 단서 |
| `-툭-` | 효과음 (따로 한 줄 또는 행동 줄 안에) | 러프·3D에 굵은 효과 글자, 감정 판정 단서(`-쾅-`은 강도 +1) |
| `@인물 "(감정·연기)대사"` | 대사 | 말한 인물, 괄호 지시는 감정 판정에, 대사는 말풍선에 |
| 그 밖의 줄 | 행동 묘사 | 인물(@ 주어)·역할·감정·포즈 판정 |
- 컷의 인물: 행동 묘사의 @주어 → 없으면 첫 대사의 인물.
- 역할 판정에는 식자를 쓰지 않는다(`[그날 밤]` 같은 시간 식자가 장면 전환으로 읽히지 않게). 감정 판정에는 쓴다(`[두근]`).
- 줄글은 '줄글 붙여넣기'로 넣으면 문장 단위로 컷 칸에 나눠 채운다.
- 검증: `test_engine.js` 컷 입력 9항목(인물, 식자, 대사, 괄호 지시, 감정, 역할).

## 9. 유저 플로우 (작성 → 연출 → 완성 → 웹툰 보기)
상단 단계 탭 네 개. 데이터베이스는 흐름 밖 도구라 상단 바 오른쪽 버튼.

| 단계 | 화면 | 하는 일 | 다음으로 |
|---|---|---|---|
| 1. 작성 | 왼쪽 씬 목록, 가운데 인물 + 씬 제목 + 컷 칸 | 인물 설정, 씬 추가·순서·삭제, 컷 입력. 미리보기 없음 | "연출 보기" |
| 2. 연출 | 씬 선택 바, 이렇게 읽었어요, 컷 표, 러프 미리보기 | 판정 확인, 값 고정, 다른 안 고르기 | "완성 방식 고르기" |
| 3. 완성 | 선택 카드 두 장 → 3D 시안 / 프롬프트 시안 | 씬마다 완성 방식 선택(씬에 기록) | "웹툰 보기" |
| 4. 웹툰 보기 | 작품 제목, 씬 목차, 세로 리더 | 모든 씬을 순서대로 이어 한 편으로 읽기, 러프/3D 보기 전환, 3D 일괄 그리기, 이미지 저장 | — |

### 데이터
- 작품 = 인물 목록(공통) + 씬 목록. 씬 = `{id, title, cuts[], out}` (out: 선택한 완성 방식). 브라우저 저장(`rough-scenes`), 예전 단일 장면(`rough-cuts`)은 씬 1로 옮긴다.
- 연출·완성은 '현재 씬' 기준. 씬 선택 바(‹ 씬 2 · 제목 ›)로 바꾼다.

### 웹툰 보기 형태
- 가운데 720px 리더 칼럼(웹툰 앱처럼), 바깥은 회색 배경.
- 맨 위: 작품 제목(고칠 수 있음), 씬 수·컷 수, 씬 목차 칩(누르면 그 씬으로 스크롤).
- 씬마다: 작은 구분선 "씬 N · 제목" → 컷 세로 스트립(컷 번호·선택 표시 없이, 패턴의 여백 그대로).
- 보기 전환: 러프(엔진 러프) / 3D(그린 씬은 3D, 안 그린 씬은 러프로 대신 표시). "3D로 모두 그리기"로 남은 씬을 차례로 렌더링.
- 저장: 전체를 한 장 PNG로(너무 길면 씬별 파일로 나눔).

## 10. 프롬프트 시안과 컷 이미지 등록

- **프롬프트 생성** (`rough/prompt.js`): 컷 배치가 정한 값을 블록으로 풀어 쓴다.
  - 화풍: 작품 공통 문장(직접 수정, 브라우저 저장). 기본값은 녹빛 레퍼런스 기준.
  - 카메라: 샷 → 프레이밍·렌즈(설정 24mm … 디테일 100mm), 앵글 → 시점, 인물 배치(좌우 1/3).
  - 인물: 인물 설정란의 외형, 감정·강도 → 구체 표정, 동작 단어 → 포즈.
  - 장소·조명: 씬 글 전체에서 장소·시간·날씨를 찾고, 컷 자체 단서가 있으면 그것을 우선.
  - 연출 맥락: 묶음의 서사·목적, 정점 여부, 앞뒤 컷.
  - 지면: 대사·식자 자리를 비우라는 지시. 글자는 넣지 않게.
  - 금지어: 글자·말풍선·워터마크·손가락 왜곡·실사풍.
- **형식**: 자연어(한국어, ChatGPT·Gemini에 그대로 붙여 넣는 지시문) 하나로 통일. `prompt.js`는 미드저니·SD 문자열도 계속 만들지만 화면에는 쓰지 않는다.
- **씬 브리프**: 등장인물 외형·장소·컷 흐름을 한 번에 담아 먼저 넣으면 컷끼리 덜 흔들린다.
- **이미지 등록**: 각 컷 카드에 생성 이미지를 놓는다(클릭·끌어다 놓기·붙여넣기).
  - 여러 장을 한 번에 넣으면 파일 이름 순으로 빈 컷부터 채운다. 특정 컷에 놓으면 그 컷부터 차례로.
  - 저장 키는 씬 id + 컷 순서. 컷 글이 바뀌면 '글이 바뀜' 표시.
  - IndexedDB에만 저장(최대 1380px JPEG).
- **웹툰 보기 '완성본'**: 등록 이미지가 있는 씬은 컷 단위로 이미지(이미지 비율 그대로), 없는 컷은 러프. 이미지가 없으면 3D 결과, 그것도 없으면 러프. '러프'는 전부 러프. 이미지 저장도 같은 규칙.

## 11. Claude로 다듬기 (선택)

- 규칙 엔진은 컷 하나씩 표를 채우는 방식이라 컷 사이 추론이 약하다. 인물 위치 관계, 들고 있는 소품, 조명 방향이 컷마다 따로 놀고, 원문에 없는 배경·자세·시선은 비워 둔다.
- 그래서 엔진값(샷·앵글·렌즈·감정·강도·비율·정점·묶음 목적)과 규칙 초안을 함께 Claude(Opus 5.5, `rough/claude.js`)에 보내 씬 전체를 읽고 다시 쓰게 한다.
  - 엔진이 정한 연출값은 바꾸지 않는다.
  - 연속성, 빈 정보 채우기, 감정을 몸 상태로, 프레임 안 구도, 글자 자리 비우기를 지시.
  - 결과는 JSON 스키마(brief + cuts[n, prompt])로 받는다.
- 사용자가 자기 API 키를 넣는다. 브라우저에서 바로 호출(서버 없음). 이미지는 보내지 않는다.
  - 키는 보안 입력창(모달)에서만 받는다: 비밀번호 입력, 자동완성·맞춤법 끔, `sk-ant-` 형식만 허용(관리자 키 거부), 저장 전 모델 조회(`models.retrieve`, 토큰 비용 없음)로 확인. 화면에는 앞 7자·끝 4자만.
  - 보관: 이 브라우저(localStorage) 또는 탭을 닫으면 지움(sessionStorage). 401이 오면 키를 지우고 창을 다시 띄운다.
  - Claude API로 고정: baseURL `https://api.anthropic.com`, 모델 `claude-opus-5-5`. 페이지 CSP의 `connect-src`를 이 사이트와 api.anthropic.com으로만 제한해 키가 다른 곳으로 나갈 수 없게 했다.
- 씬별로 입력 서명과 함께 저장. 글·화풍·인물 외형이 바뀌면 "다시 다듬으면 반영돼요" 표시. '기본'으로 규칙 결과와 비교 가능.
- SDK는 `@anthropic-ai/sdk` 1.6.0을 esbuild로 묶어 `rough/vendor/anthropic-sdk.mjs`에 둔다(Apache-2.0).

## 12. 출력 규격·컷 연출 상세·컷 간격

- **출력 규격**(모든 컷 프롬프트 맨 위): 비율 `가로 100 : 세로 N`, 권장 픽셀(가로 1024 기준), 가장 가까운 표준 비율(1:1, 4:5, 3:4, 2:3, 9:16, 1:2 등)과 맞지 않으면 잘라 맞추라는 안내, 한 장에 한 컷·테두리 없음. 카드에도 검은 배지로 표시.
- **컷 연출 블록**: 연출 의도(VNG 역할·묶음 목적·샷 이유) / 카메라(샷·앵글·카메라 높이·렌즈·심도) / 구도(3분할 배치·머리 위 여백·앞중뒤 레이어·첫 시선) / 인물과 연기(외형·위치·방향·시선·거리·표정·몸) / 동작 / 장소·조명(주광 방향) / 앞뒤 컷과의 이어짐(전환 종류·180도 선·뒤 간격) / 비워 둘 자리(말풍선·글상자 위치와 크기) / 하지 말 것.
  - 디테일(인서트): 얼굴 대신 손·소매·장갑으로 인물을 알아보게, 손의 힘으로 감정.
  - 설정·전경: 표정보다 자세와 실루엣.
- **컷 간격 = 중요도 단계**: 다음 컷과의 관계로 붙임·보통·쉼·큰 쉼을 정하고, 패턴 여백과 섞은 뒤 단계 범위 안으로 고정.
  - 붙임(0.06~0.12): 즉각 반응(순간 전환), 같은 인물 연속 동작.
  - 보통(0.13~0.32): 기본, 대사 주고받기는 좁게.
  - 쉼(0.33~0.64): 정점 앞 뜸, 감정 하강, 분위기 컷 사이, 묶음 끝.
  - 큰 쉼(0.65~1.2): 다음 컷이 장면 전환, 정점 뒤 감정이 꺾임, 정점이나 여운으로 묶음이 끝남.
  - 컷 표 '길이' 아래에 `↓ 단계 · 이유`로 표시, 프롬프트에는 그 컷을 어떻게 끝맺을지(붙임=동작 도중, 큰 쉼=완결된 그림)로 반영.

## 13. 참고 시트 PNG (한 장)

- 프롬프트 시안에서 씬 하나를 **한 장의 PNG**로 내보낸다. 생성 도구에 프롬프트와 함께 이 한 장만 올리면 된다.
  - A 인물: 등장인물마다 캐릭터 참고 이미지(없으면 외형 설명 박스) + 이름·외형.
  - B 장면·색·화풍: 이 씬에 연결된 장면 참고 이미지, 팔레트, 화풍 문장.
  - C 컷 구도: 컷마다 러프(패널만 잘라서), 번호, 비율, 샷·앵글·인물, 아래에 엔진이 고른 구도 레퍼런스('구도 참고').
- 컷 프롬프트에 `■ 참고 이미지` 블록을 넣어 시트의 어느 칸을 무엇에 쓰는지 지정: 인물=A칸 그림과 똑같이(그림이 없으면 설명대로), 색=B칸, 구도=C칸 '컷 n' 러프의 위치·크기·카메라만(러프의 선·회색·번호는 그리지 않음), '구도 참고'는 화면 분할과 시선 흐름만.
- Claude 다듬기도 같은 블록을 유지한다. 미리 보기 버튼으로 화면에서 먼저 확인할 수 있다.

## 14. NovelAI V4.5 시안 (별도 메뉴)

- 완성 단계의 세 번째 선택지. 씬마다 3D / 프롬프트 / NovelAI 중 고른다. 출력은 NovelAI Diffusion V4.5 Full 화면 칸에 맞춘 태그(`rough/nai.js`) — 자연어 통일 원칙의 예외.
- 컷마다 칸별 복사:
  - 기본 프롬프트: 인원 태그(1girl·1boy) + 샷·앵글 + 장소 + 빛(시간대 하나 + 날씨) + 분위기 + 정점 강조 `1.2::dramatic lighting::` + 대사 컷이면 negative space + 화풍 태그.
  - 캐릭터 프롬프트(최대 6명): 외형 태그(인물 설정 외형을 자동 변환, 사용자가 고친 태그 우선) + 주인공 표정·동작 + 방향. 위치는 5×5 칸(A~E·1~5)과 좌표.
  - 해상도(64 배수, 1024×1024 면적 이내에서 컷 비율에 가장 가깝게, 안 맞으면 자를 방향), Steps 28 · Guidance 5 · Euler Ancestral · karras.
  - img2img 바탕 PNG: 그 컷의 러프를 NovelAI 해상도로, 글자·말풍선·이름표 없이 선만. Strength는 샷에 따라 0.62~0.72.
  - 레퍼런스: 주인공 캐릭터 이미지가 있으면 Character Reference(한 장), 없고 장면 이미지가 있으면 Vibe Transfer(V4.5에서 둘은 같이 못 씀). 이미지 저장 버튼.
- 생성 이미지는 프롬프트 시안과 같은 컷 이미지 저장소에 등록돼 웹툰 보기 완성본으로 이어진다.
- 설정값은 시작점이다. NovelAI 쪽 기능·제한은 공식 문서 기준으로 다시 확인할 것.

## 15. 3D 시안 제거

- 완성 방식은 프롬프트 시안과 NovelAI V4.5 시안 두 가지만 남긴다. 3D 시안(VRoid 툰 렌더, three.js·three-vrm·모델 파일)은 저장소에서 지웠다(이전 커밋 기록에는 남아 있음).
- 웹툰 보기 완성본은 등록한 컷 이미지, 없는 컷은 러프. 예전에 3D로 골라 둔 씬은 선택 안 함으로 되돌린다.
- 인물 설정의 여자/남자 선택은 NovelAI 인원 태그(1girl·1boy)에 계속 쓴다.
- 러프 미리보기와 웹툰 보기 '러프'에 엔진이 고른 구도 레퍼런스를 컷마다 컬러로 깐다(불투명도 0.55, 러프 선은 위에). 직접 넣은 캐릭터·장면 참고 이미지가 맞는 샷에서는 그쪽이 우선. 미리보기 위 '레퍼런스' 버튼으로 끄고 켠다(브라우저에 기억). 참고 시트와 NovelAI 바탕 PNG에는 깔지 않는다.

## 16. NovelAI 시안 수정

- 제외할 내용(Undesired Content) 칸은 출력하지 않는다. NovelAI 쪽 기본 프리셋을 그대로 쓴다.
- NovelAI 시안에도 Claude로 다듬기: 프롬프트 시안과 같은 키(보안 입력창, Opus 5.5 고정). 엔진값과 규칙 태그 초안을 보내고, 컷마다 기본 프롬프트와 캐릭터 프롬프트·위치(A1~E5)를 JSON 스키마로 받는다. Danbooru 태그만, 가중치는 `1.2::tag::`, 180도 선 유지, 소품·의상 연속성. 씬별로 서명과 함께 저장, 기본/Claude 전환, 글·태그가 바뀌면 다시 다듬으라고 표시.
- 키 입력창은 보기와 상관없이 뜨도록 페이지 최상단 쪽으로 옮겼다.
- NovelAI 컷 카드의 '전체 복사'는 기본 프롬프트와 캐릭터 프롬프트만, 각 끝에 쉼표, 빈 줄로 구분해 복사한다(해상도·위치·설정 등은 빼고). Claude로 다듬은 결과를 보고 있으면 그 내용으로.

## 17. 레퍼런스 첨부를 작성 단계로 (캐릭터챗 UI)

- 인물·배경 이미지는 모두 작성 단계에서 넣는다. NovelAI 단계에는 요약(아바타·개수)과 "작성에서 편집" 버튼만 둔다.
- **등장인물 카드**: 캐릭터챗의 프로필 카드처럼 3:4 대표 이미지(없으면 이름 첫 글자 + 이름별 색), 이름·성별·호칭, 외형 두 줄, 태그 칩(NovelAI 태그), 이 씬 등장 컷·대사 수. 마지막 칸은 '+ 새 캐릭터'. 글에서 찾은 미등록 이름은 칩으로 제안, 누르면 바로 프로필 창.
- **캐릭터 프로필 창**: 왼쪽 대표 이미지(클릭·끌어다 놓기·붙여넣기, 팔레트), 오른쪽 이름·다른 호칭·성별·외형(300자)·NovelAI 태그, 아래 '대사 미리보기'(이 인물의 실제 대사를 채팅 말풍선으로). 이름을 바꾸면 대표 이미지와 태그가 따라간다. 삭제 시 이미지도 함께 지운다.
- **배경·분위기 카드**: 장소 이미지 여러 장, 이름 수정, 팔레트.

## 18. 캐릭터 페이지와 캐릭터 보관함

- 단계: 1 캐릭터 → 2 작성 → 3 연출 → 4 NovelAI → 5 웹툰 보기. 작성 단계에는 등장인물 요약(아바타·@이름)과 '캐릭터 페이지에서 편집'만 남긴다.
- 외형은 1,000자까지.
- **재사용 구조**: 작품의 등장인물은 보관함 항목의 복사본(`c.lib`로 연결). 작품에서 고쳐도 보관함은 그대로이고, 프로필 창의 '보관함 갱신'으로 반영하거나 '보관함 버전으로'로 되돌린다. 카드에 '보관함' / '보관함과 다름' 표시.
  - 연결 상태를 바로 동기화하지 않는 이유: 작품마다 의상·나이 등이 달라질 수 있고, 한 작품의 수정이 다른 작품을 바꾸면 안 되기 때문.
- **보관함 화면**: 캐릭터 페이지 아래. 검색(이름·외형·태그), 성별 필터, 카드마다 '작품에 넣기'(이미 쓰는 중이면 표시만)·삭제, '모두 보관함에 저장'.
- 보관함은 이 브라우저(localStorage + IndexedDB 이미지)에 남고 작품을 지워도 유지. 다른 기기로는 '파일로 내보내기'(이미지 포함 JSON) → '가져오기'.
- 작품에서 빼기는 작품에서만 빠지고 보관함 항목은 남는다.

## 19. 캐릭터 카드에서 바로 편집

- 프로필 창(모달)과 대사 미리보기를 없애고, 캐릭터 페이지의 카드에서 바로 고친다: 왼쪽 대표 이미지(클릭·끌어다 놓기·붙여넣기, × 로 지우기, 팔레트), 오른쪽 이름·성별·보관함 상태, 다른 호칭, 외형(1,000자), NovelAI 태그, 아래 보관함 저장/갱신·보관함 버전으로·작품에서 빼기.
- 글자를 치는 동안에는 카드를 다시 그리지 않고 글자 수·보관함 상태·자동 태그 안내만 바꾼다(포커스 유지). 이름은 입력을 마칠 때 확정해 이미지·태그를 새 이름으로 옮긴다.
- '+ 새 캐릭터'와 글에서 찾은 이름 칩은 새 카드를 만들고 그 카드로 스크롤·포커스.
- 카드 상자 대신 목록형: 캐릭터 사이에 얇은 회색 선. 대표 이미지는 너비 약 1/4(최소 180px)이고 오른쪽 입력 칸 높이만큼 늘어난다. 그 아래 컬러 팔레트를 둥근 사각형 다섯 칸 한 줄로. 모바일은 위에 4:3 이미지, 아래 입력 칸.

## 20. 세계관 탭 (캐릭터 다음)

- 단계: 1 캐릭터 → 2 세계관 → 3 씬 → 4 콘티 → 5 작화(NovelAI V4.5) → 6 편집. (웹툰 제작 공정 용어로 통일) 구성은 캐릭터 페이지와 같다(바로 고치는 목록 + 보관함).
- 요소는 캐릭터챗 사이트의 세계관 설정과 로어북(키워드로 불려 나오는 설정 노트)을 따름.
  - **세계관 개요**: 대표 이미지, 이름, 장르, 시대·배경, 분위기·톤, 한줄 소개(80자), 상세 설정(3,000자), NovelAI 태그(모든 컷 기본 프롬프트에 붙음).
  - **설정 항목**: 분류(장소·세력·조직·물건·용어·개념·역사·사건·규칙·체계), 이름, 키워드, 설명(1,000자), NovelAI 태그, 이미지. 분류 필터. 이 씬 몇 컷에 나오는지 표시.
- **적용 방식(로어북)**: 컷 글(행동·식자·대사)에 항목 이름이나 키워드가 나오면 그 컷의 NovelAI 기본 프롬프트에 항목 태그가 붙는다. 장소 항목 이미지는 그 묶음의 배경 레퍼런스(Vibe Transfer·참고 시트)로 우선 쓰인다. Claude 다듬기(NovelAI)에는 세계관 개요와 이 씬에 나오는 항목 설명을 함께 보낸다.
- **세계관 보관함**: 개요와 항목을 함께 보관(분류 필터·검색), 작품에 넣기(개요는 교체 확인), 보관함과 같음/다름 표시와 갱신·되돌리기, 파일로 내보내기/가져오기(이미지 포함 JSON).
- 씬 단계 위쪽에 세계관 요약과 "세계관 페이지에서 편집" 버튼.

## 21. 편집 화면 (포스타입·노션 에디터 참고)

- 들어오면 바로 편집 상태. '배치 편집' 토글 대신 '미리보기'(손잡이·속성 패널 숨김)로 바꾸고, 다시 누르면 '편집으로'.
- 3단 구성: 왼쪽 목차(씬 → 컷 트리, 이미지 등록 여부 점, 누르면 그 컷 선택·이동) / 가운데 캔버스(큰 제목 입력, 690px 원고) / 오른쪽 속성 패널(선택한 식자: 문구·형태·연결·꼬리·크기 → 컷: 배경색·전환 질감·초기화). 아무것도 고르지 않았을 땐 조작법 안내.
- 위쪽 고정 바: 편집 · 저장 상태('저장됨 · 방금'), 완성본/러프, 실행 취소·다시 실행(Ctrl+Z / Ctrl+Shift+Z, 0.6초 안의 연속 드래그는 한 번으로 묶음, 최대 100단계), 미리보기, 이미지 저장.
- Esc로 선택 해제. 좁은 화면은 목차를 숨기고, 모바일은 속성 패널이 아래 시트(접힘 52px, 식자를 고르면 자동으로 펼침).

## 22. 씬 화면 (포스타입 에디터 참고)

- 위쪽 고정 바: 씬 · 저장 상태('저장됨 · 방금') / 넣기 도구막대([ ] 식자, @ 대사, -♪- 효과음, + 컷, ¶ 줄글) / 콘티 보기. 넣기는 마지막으로 쓰던 컷의 커서 자리에 형식을 넣고, 대사는 인물 목록을 바로 띄운다.
- 3단: 왼쪽 씬 목록(시리즈 글 목록처럼) / 가운데 원고지(흰 종이, 큰 씬 제목, 컷 수·대사·식자·효과음 집계, 테두리 없는 컷 블록) / 오른쪽 씬 정보(등장인물·세계관 요약과 편집 링크, 배경·분위기 이미지, 쓰는 법).
- 컷 블록: 번호를 끌어 순서 바꾸기, 마우스를 올리거나 쓰는 중일 때만 위·아래·삭제 버튼. 블록 아래 '해석 줄'에 엔진이 읽은 결과(인물 아바타, 대사와 연기, 식자, 효과음, 세계관 항목)를 칩으로 보여 준다.
- 좁은 화면은 오른쪽 정보를 숨기고, 모바일은 씬 목록을 위 가로 줄로.
- 씬 정보 패널: '편집' 링크는 작은 회색 글자(마우스를 올리면 밑줄)로 낮추고, 등장인물은 2열 상자(아바타·이름·이 씬 컷/대사 수, 이 씬에 없으면 흐리게).
- 씬 정보 패널에서 배경·분위기 칸을 뺐다(배경 레퍼런스는 세계관의 장소 항목 이미지로). 세계관은 한 줄 상자(아이콘·이름·장르·시대·설정 항목, 넘치면 말줄임, 마우스를 올리면 전체).

## 23. 레퍼런스를 원본 컷 전체로

- 이미지 툴로 만든 레퍼런스(`rough/references/`의 녹빛 39장 + 클로즈업 15장)를 지우고, 비공개 cuts 저장소에 모아 둔 네이버 원본 컷 전체(이두나! 872 + 녹빛자정의 연인 625 = 1,497장, 원본 그대로)를 `rough/cuts/`에 넣었다. 권리자 허락을 받은 비상업 공개.
- `rough/cuts/index.json`: 컷표(db.json)와 manifest.csv를 합쳐 그림 컷 1,163장의 샷·앵글·역할·감정·높이 비율. 러프·콘티 표 '참고'·참고 시트의 구도 레퍼런스가 여기서 나온다.
- 패턴의 출처 컷이 그대로 있으므로, 컷 배치에 쓰인 패턴 컷이 레퍼런스로 정확히 매칭된다(예: GM-04-050 패턴 컷 → GM-04-050 원본).
- DB 탭 썸네일도 공개 `rough/cuts/`에서 읽고, 없으면 예전 `../cuts/`를 본다.

## 24. 러프 = 원본 컷만, 코드 그림·식자 빼기

- 코드로 그리던 러프 그림(막대 인물·원·사각형)을 모두 뺐다. 칸에는 등록 이미지 → 원본 컷 레퍼런스(그림 영역만 잘라, 원래 색 그대로) → 둘 다 없으면 빈 칸에 '샷 · 앵글'만.
- 원본 컷 1,163장을 이미지로 자동 판정해 `cuts/index.json`에 그림 영역 상자(art)와 분류(fit)를 넣었다: ok(그림 위주) 622 / partial(말풍선 위주·그림이 덜 차지) 384 / multi(여러 칸이 섞이거나 잘림) 157. 레퍼런스는 ok만 쓰고, 패턴 출처 컷이 partial·multi면 같은 작품·같은 역할·같은 감정의 비슷한 샷 컷으로 대신한다.
- 콘티 미리보기에서는 우리가 얹던 말풍선·효과음을 빼고 식자만 남긴다(배치 참고용). 편집 단계의 식자는 그대로.
- 작화의 img2img 바탕 PNG도 코드 러프 대신 그 컷의 원본 레퍼런스를 흑백으로 잘라 만든다(레퍼런스가 없으면 만들지 않음).
- 한계: 원본 그림 안에 그려진 말풍선은 지우지 못한다. 그림 밖 여백에 있던 말풍선은 그림 영역 자르기로 빠진다. 분류는 자동이라 일부 틀릴 수 있다.

## 25. 말풍선 제거본 폴더와 칸 모양

- `rough/cuts/` = 원본(말풍선 있음), `rough/cuts-clean/` = 같은 경로·같은 파일 이름의 말풍선 제거본. 같은 컷은 이름으로 짝지어진다. 러프·콘티 레퍼런스와 작화 바탕 PNG는 제거본을 쓴다.
- 제거는 자동(`tools/declutter.py`, `tools/batch_clean.py`): 칸 안쪽에서 고른 흰·미색 영역 + 그 안에 글자 획처럼 작은 진한 조각이 6개 이상 줄지어 있는 것만 말풍선으로 보고, 주변 색으로 메운 뒤 가장자리를 흐린다. 얼굴·흰 셔츠가 지워지지 않도록 기준을 엄격하게 잡아서, 그림 컷 1,163장 중 281장에서만 지웠다. 칸 경계에 걸친 말풍선의 바깥쪽, 회색·색 말풍선, 어두운 바탕의 흰 글자, 장식 식자 상자, 효과음은 남는다(칸 밖 여백의 말풍선은 그림 영역 자르기로 빠짐).
- 칸 모양: 그림 영역 위·아래 띠의 좌우 끝으로 네 꼭짓점(quad)을 잡아 사각 814 / 사선 349로 판정. 사선 칸 레퍼런스가 들어간 러프 칸은 그 모양대로 잘리고 테두리도 사선으로 그린다. 콘티 표 레퍼런스 라벨에 '사선 칸' 표시.
- DB 탭에서 컷을 누르면 원본과 제거본을 나란히, 칸 모양과 레퍼런스 사용 여부(그림 위주 / 말풍선 위주 / 여러 칸 섞임)를 함께 보여 준다.

- (갱신) 원본 컷 jpg는 `.gitignore`의 `*.jpg` 때문에 그동안 실제로는 올라가지 않았다. `!rough/cuts/**/*.jpg` 예외를 넣어 이번에 실제로 올렸다. 자동 말풍선 제거본(`rough/cuts-clean/`, 마찬가지로 올라간 적 없음)과 처리 스크립트는 지웠다. 말풍선 정리는 피그마에서 손으로 하기로 하고, 레퍼런스 제외 컷을 피그마 새 파일로 옮기는 작업을 3장으로 시험했다. 칸 모양(quad·frame)과 분류(fit)는 index.json에 그대로 둔다.

## 26. 피그마 수정본 받아오기

- 피그마 파일 "웹툰 레퍼런스 컷 정리"에서 컷마다 `컷ID 원본` 프레임(원본 크기 690×h, 원본 이미지가 채워짐) 위에 말풍선을 지우는 레이어를 얹거나 이미지를 바꿔 고친다. 프레임 이름은 그대로 둔다.
- 다 고친 컷은 묶음 이름 끝에 `완료`를 붙이거나(예: `GM-06-008 완료`) 컷 ID를 알려 주면, Claude가 그 `원본` 프레임을 원본 크기 jpg로 내보내 `rough/cuts-fixed/`에 원본과 같은 경로·같은 이름으로 저장하고 `tools/apply_fixed.py`로 index.json에 `fixed`를 기록한다.
- 툴은 수정본이 있으면 원본 대신 수정본을 레퍼런스로 쓰고, 레퍼런스 제외(말풍선 위주·여러 칸) 컷이라도 수정본이 있으면 레퍼런스 후보에 다시 넣는다. 콘티 라벨에 '수정본', DB 상세에 원본·수정본을 나란히.
- 피그마 내보내기를 받으려면 네트워크에 mcp.figma.com(업로드)·www.figma.com(내보내기)이 필요해 기본 환경 허용 목록에 추가했다.

## 27. 편집: 칸 프레임 끌어 바꾸기

| 피그마 | 레이어 이름 붙은 SVG 한 파일. 캔버스에 끌어다 놓기 | 씬·컷 그룹, 칸(벡터 다각형), 그림(칸 모양 마스크 안 이미지, 다시 자르기 가능), 말풍선·효과음·나레이션(벡터 + 텍스트) | 글꼴(Pretendard)이 없으면 대체 글꼴. 여러 줄 대사는 줄마다 텍스트 레이어. 씬이 프레임이 아니라 그룹으로 들어감 |
| 클립스튜디오 | 씬마다 PSD 한 장 + 대사 목록.txt를 ZIP으로 | 배경 / 컷 폴더 / 칸 / 그림(레이어 마스크 = 칸 모양) / 식자 하나씩 레이어 | 식자는 그림(래스터) 레이어. 말풍선 레이어·텍스트 레이어로는 못 들어감 → 대사 목록으로 다시 입력. .clip 원본 형식은 공개 사양이 없어 직접 못 씀 |
| Photoshop 등 | 같은 PSD | 위와 같음 | 위와 같음 |

- 방식: 내보낼 때만 식자를 그룹으로 감싸(`LAYER_TAGS`) 레이어를 나누고, 원본 컷 크롭용 중첩 `<svg viewBox>`는 이미지+사각 클립으로 풀고, 그림은 모두 data URL로 파일 안에 넣음. 흑백 레퍼런스 필터는 픽셀에 미리 구움(피그마는 SVG 필터를 버림).
- PSD는 ag-psd 34.1.0(MIT)을 `vendor/`에 두고 PSD를 고를 때만 불러옴(페이지 CSP가 외부 스크립트를 막음). ZIP은 자체 구현, 브라우저가 지원하면 deflate 압축.
- 함께 고침: `<g data-art>`처럼 값 없는 속성 때문에 SVG가 XML로 안 읽혀 PNG 저장이 실패하던 문제, PNG에서 원본 컷 레퍼런스 그림이 빠지던 문제(외부 주소 이미지).
- 확인: 헤드리스 Chromium에서 세 형식 저장 → psd-tools로 레이어 트리·마스크 확인, PSD 합성·SVG 렌더·PNG가 편집 화면과 같음.
- 다음 후보
  1. 피그마 플러그인: 같은 데이터를 JSON으로 내보내고 플러그인이 씬=프레임, 대사=텍스트 노드(한 덩어리), 그림=이미지 채우기로 만들기. SVG보다 깔끔하지만 플러그인 배포가 필요.
  2. PSD 텍스트 레이어: Photoshop용으로 대사를 텍스트 레이어로도 넣기(클립스튜디오는 PSD 텍스트를 그림으로 읽는 것으로 알려져 있어 효과는 Photoshop 위주).
  3. 클립스튜디오 세로 스크롤 캔버스 규격에 맞춘 폭·해상도 선택(690px 1배 / 2배 / 300dpi 원고).

- **수집 스크립트 보존**: `tools/pipeline/`(README에 순서·형식), 손 판정 원본 111개 파일(`notes/`). 새 폴더에서 다시 돌려 기존 결과와 같음을 확인.
- **DB 사본·패턴 갱신**: `db/db.json`을 시트 리비전 164(5작품 5,078컷 · 5컷 묶음 742 · 장면 314)로. `tools/build_patterns.py`로 패턴 244 → 742개(기존 GM 109개는 완전히 같고, DN은 앵글 '미검증'이 실제 값으로).
- **썸네일**: `tools/build_thumbs.py`로 5,078장 WebP(240×360 안, 합계 23.8MB, 한 장 평균 약 4.8KB). 레퍼런스 탭·DB 표·연출 사전에서 사용, 실패하면 원본.
- **첫 로딩 줄이기**: `tools/build_index_min.py`로 `cuts/index.min.json`(열 단위, 사선 칸만 꼭짓점, 쓰지 않는 필드 제외) 1,553KB → 503KB(gzip 156 → 83KB). DB 화면은 manifest.csv(0.7MB) 대신 컷 ID로 경로 계산. 처음 받는 데이터 합계 1.83MB → 1.37MB(패턴이 3배로 늘었는데도).

## 39. 클립스튜디오 비교 개선안 P0 (작업물이 틀어지는 문제)

외부 비교 리뷰(불편한 점 46개)에서 작업물에 직접 영향을 주는 네 가지를 먼저 고침.
- **컷을 옮겨도 이미지가 따라감(#1):** 컷 이미지는 패널 번호로, 컷 글·편집값은 컷 순번으로 저장돼 있어 순서를 바꾸면 그림이 다른 컷에 붙었음. `remapCuts(씬, 작업)`이 작업 전후 패널을 비교해 이미지를 같은 컷의 새 패널 번호로 옮김. 드래그 정렬·위/아래·삭제·Ctrl+Enter 끼우기·칸 나누기 모두 이 함수를 거침. 글이 그대로면 '글이 바뀜'도 붙지 않음. 지운 컷의 이미지는 같이 지움
- **저장 실패를 알림(#36):** 원고(localStorage)·이미지(IndexedDB) 저장이 실패하면 '저장됨' 대신 '저장 안 됨'을 계속 띄우고 처음 한 번 알림. 다음 저장이 성공하면 풀림
- **완성본 점검(#2·#45):** 이미지를 올린 원고면 편집 화면 위에 '이미지 없음 N컷 · 글이 바뀜 M컷'과 '다음 확인 ›'(해당 컷으로 이동). PNG·SVG·PSD 내보내기 전에도 한 번 묻고, '먼저 확인하기'를 누르면 첫 문제 컷으로 이동
- **되돌리기에도 이미지 위치 포함:** 실행 취소 기록에 씬별 이미지 위치(패널 번호·이미지 uid·sig)를 함께 저장. 그림 데이터는 IMG_POOL에 두고 uid로만 가리켜 기록이 가벼움. Ctrl+Z·Ctrl+Shift+Z로 컷 순서를 되돌리거나 다시 하면 이미지도 제자리로 가고 '글이 바뀜'도 원래대로
- 다음 순서: 납품 분할·제목 없는 PNG(#43·#44) → 씬 경계 배경색 유지(#8) → 회차 백업 파일(#34·#35)

## 40. 연재용 분할 내보내기 (#43·#44)

- 내보내기 메뉴 '연재용 분할 (JPG·PNG)': 폭·한 장 최대 높이·형식·JPG 품질·씬 사이 간격을 정해 여러 장을 ZIP으로(`제목_001.jpg` …). 설정은 기억함
- 씬 제목은 기본으로 넣지 않음(검수본용으로 켤 수 있음). 씬끼리 이어 붙임
- 자르는 위치: 한 줄이 모두 같은 색인 줄(컷 사이 여백)을 아래쪽 60%에서 먼저 찾고, 없으면 위쪽까지 찾음. 한 장 높이보다 긴 컷만 그림 위에서 자르고 그 수를 알려 줌
- 예시 원고(690×12,825px, 1,280px 기준) → 15장, 그림 위에서 자른 곳 2군데(둘 다 1,280px보다 긴 컷)
- 기존 'PNG 이미지'(한 장·씬 제목 포함)는 확인·공유용으로 그대로 둠

## 41. 씬 경계 배경색 유지 (#8)

- 씬 마지막 컷의 아래 전환이 흰색으로 끝나던 것을, 기본으로 **다음 씬 첫 컷의 배경색**으로 이어지게 함. 씬 SVG 아래 24px 여백도 같은 색으로 채워서 내보낸 이미지에서 이음매가 안 보임
- 씬의 마지막 컷을 고르면 속성 패널에 '씬 끝 색'(다음 씬 첫 컷 색으로 이어감 · 이 컷 배경색 유지 · 흰색으로). 마지막 씬은 기본이 흰색. 실행 취소 기록에 포함

## 42. 작업 파일·이전 버전 (#34·#35·#37)

- 내보내기 메뉴 '작업 파일 저장': 브라우저에 있는 러프 툴 설정·원고(localStorage의 rough-*)와 이미지(IndexedDB)를 `.rough.json` 한 파일로. AI 키는 넣지 않음. 다른 기기·브라우저에서 '작업 파일 불러오기'로 그대로 이어서 작업(지금 작업을 바꾸기 전에 확인)
- 효과음 소재 ZIP(사용자가 따로 가져온 묶음)은 파일에 넣지 않음 → 새 기기에서는 다시 가져와야 함
- '이전 버전': 저장이 일어날 때 10분에 한 번 원고(씬·컷 글·편집값)를 IndexedDB에 남김(최근 30개). 목록에서 골라 되돌리고, 되돌리기 직전 상태도 하나 남김. 컷 이미지는 그대로

## 43. 그라데이션 편집·배경 이미지 소재·씬 팔레트 (#9·#12·#13)

- **전환 중간색·위치(#9):** 컷마다 아래 전환의 중간색(켜기/끄기)과 위치(위→아래 5~95%)를 직접 정함. 프리셋 질감의 중간색·위치를 덮어씀
- **배경 이미지 소재(#12):** 속성 패널 '배경 이미지'에서 PNG·JPG를 올리면 소재 목록에 남고(IndexedDB, 작업 파일에도 포함), 어떤 컷의 아래 전환에든 골라 깔 수 있음. 위아래는 부드럽게 사라지고 진하기 조절. 목록에서 지우면 쓰던 컷에서도 빠짐
- **씬 색 한 번에 바꾸기(#13):** 이 씬에서 쓰는 배경색·전환 중간색을 모아 보여 주고, 색마다 새 색을 고르면 같은 색을 쓰는 곳이 함께 바뀜(Ctrl+Z로 되돌리기)
- 남은 것: 전환 방향(사선·가로)과 컷 그림 위에 색을 얹는 보정 레이어(#10)는 아직 없음

## 44. PSD 글자를 텍스트 레이어로 (#40)

- 말풍선·나레이션은 컷 폴더 안에서 '모양'(그림)과 '글자'(텍스트 레이어)로 나뉨. 글자 레이어에는 문구·글꼴(작품 글꼴 이름 + 굵기)·크기·행간·자간·색·정렬이 들어가고, 텍스트를 못 읽는 앱을 위해 미리보기 픽셀도 함께 넣음(ag-psd `invalidateTextLayers`로 포토샵은 열 때 다시 그림)
- 효과음은 소재 그림이라 그대로 그림 레이어
- 확인: 내보낸 PSD를 ag-psd로 다시 읽어 텍스트·크기·글꼴·정렬·위치가 남는 것까지. 클립스튜디오·포토샵에서 직접 열어 본 확인은 아직 못 함(클립스튜디오가 PSD 텍스트 레이어를 텍스트로 여는지는 버전에 따라 다를 수 있어 대사 목록.txt는 계속 넣음)

## 45. P2 편집 편의 (#18·#6·#19·#29·#31)

- **나레이션 여러 개(#18):** 한 컷에 `[…]` 줄을 여러 개 쓰거나 나레이션 도구(T)로 여러 번 누르면 상자가 따로 생김(키 caption, caption-1…). 둘째부터는 위로 쌓여 놓이고 각각 옮기기·문구 고치기. 엔진 출력에 `captions` 배열 추가(기존 `caption`은 ' / '로 이은 값 그대로)
- **씬 전체 맞춤(#6):** 속성 패널 '씬 전체에' → 폭·좌우 맞춤(고른 컷의 x·폭을 같은 씬 모든 컷에, 높이는 각자 유지) / 간격 맞춤(아래 간격을 모든 컷 사이에)
- **대사 교정(#19):** 편집 화면 상단 '대사 교정' → 모든 씬의 대사·나레이션·효과음 줄을 씬·컷 순서로 한 화면에. 칸을 고치면 원고에 바로 반영, 찾기·모두 바꾸기, 맞춤법 검사(브라우저). 편집 화면에서 직접 고친 문구가 있는 씬은 그 사실을 알려 줌
- **상세 분석 검색(#29):** 레퍼런스 검색이 컷표 '상세 …' 열(근거·영역 열 제외)도 찾음. 상세에서 맞으면 툴팁에 앞뒤 문장. 예: '흰 여백' → 11컷(제외 컷 빼고)
- **시퀀스 템플릿(#31):** '이 컷부터 저장'(몇 컷·이름) → 크기·간격·배경·전환·배경 이미지·효과선을 템플릿으로(글·레퍼런스·식자 제외). 다른 씬에서 '이 컷부터 적용'. 브라우저에 저장되고 작업 파일에도 들어감

## 48. 콘티·작화 합치기 (단계 7 → 6)

같은 컷을 두 화면에서 두 번 찾던 흐름(콘티에서 샷 고치고 → 작화로 가서 그 컷에 그림 넣기)을 한 화면으로.

## 49. 씬 문법 확장: 연출 지시 {…}

편집 화면에서 손으로 하던 연출을 씬 글에 적어 두면 콘티·편집·내보내기에 그대로 적용. 문법 설명 원문은 `rough/grammar.js`의 `GUIDE`.

- 줄 어디에나 `{…}`, 여러 개는 쉼표: `{클로즈업, 로우앵글, 확대 1.5}`
- 엔진이 읽는 것(engine.js `readDirs`): 샷·앵글(별칭 포함), 칸 길이(짧게·길게·아주 길게·길이 1.5), 다음 컷 간격(붙임·쉼·큰 쉼), 하이라이트. 자동 판정보다 우선하고 근거에 '글에 적은 연출'로 표시
- 화면이 읽는 것(grammar.js): 확대 1.5/200%, 집중선·속도선(진하게·방향·위치·색), 배경 색/분위기 프리셋(별빛·불씨…), 간격 px, 씬 끝 배경, 말풍선 모양(속삭임·외침·생각·전화·분노·숨·떨림·의미심장)
- 말풍선: 대사 줄의 `{외침}` → 그 대사, 대사 메모 `(속삭이며)` → 자동, 다른 줄의 `{생각}` → 컷의 모든 대사
- 효과음 크기: `-쿵-` 보통 · `--쿵--` 크게(160%) · `---쿵---` 아주 크게(220%)
- **우선순위:** 편집 화면에서 직접 바꾼 값 > 글에 적은 연출 > 자동. 글의 연출은 저장값을 바꾸지 않고 그릴 때 겹침(글을 지우면 사라짐)
- 씬 화면: 툴바 `{ } 연출` 메뉴(누르면 지금 줄 끝에 넣고, 이미 `{…}`가 있으면 쉼표로 이어 붙임), 컷 아래 '연출 · …' 해석 칩, 못 읽은 낱말은 '모르는 연출'로 빨갛게. 메뉴에서 '문법 전체 보기'·'AI용 문법 설명 복사'
- 구성안 생성(Claude) 프롬프트에 문법 규칙을 붙여, 생성된 컷 글이 처음부터 지시를 포함(의도가 분명한 곳에만, 컷당 0~3개)
- 컷 식자 지우기·대사 교정은 줄의 `{…}`를 보존. 엔진 평가(742묶음) 결과는 변경 전과 동일

## 50. 씬 글 위에 문법 칠하기 · 대사와 묘사 줄 나누기

## 52. 씬 화면 오른쪽 실시간 미리보기 (보기 전용)

- 오른쪽 패널 = 미리보기 하나(인물·세계관 요약, 머리줄·완성본/러프 전환은 뺌). 1101px 이상에서 폭 340px
- 편집 화면과 같은 그리기(`renderSVG`): 연출 지시·편집에서 직접 고친 배치·등록 그림(없으면 레퍼런스)·배경 전환·말풍선이 그대로
- **스크롤만 가능, 누르거나 고치는 동작 없음. 바꾸는 건 왼쪽 글(문법)로만.** 글을 고치면 계산(0.35초 뒤) 직후 다시 그림, 글 칸을 고르면 그 컷을 파랗게 표시하고 따라 스크롤
- 1100px 이하에서는 기존처럼 오른쪽 패널이 숨겨짐

## 53. 씬 화면 컷 카드 · 컷 사이 +

- 컷마다 테두리 상자(카드)로 구분. 마우스를 올리면 테두리가 진해지고, 쓰는 중인 컷은 파란 테두리 + 옅은 빛. 배경색 띠는 카드 왼쪽 안쪽에
- 카드 사이 간격은 연출 간격에 따라 붙임 8 · 보통 18 · 쉼 36 · 큰 쉼 72px
- 카드 아래 가운데 '+'(마우스를 올리면 보임, 휴대폰은 늘 흐리게): 그 컷 바로 아래에 빈 컷을 넣고 바로 쓰기. 이미지·편집값도 한 칸씩 밀림. 기존 추가 방법(맨 아래 '+ 컷 추가', 툴바 '+ 컷', Ctrl+Enter)은 그대로

## 54. 콘티 = 컷별 프롬프트 + 그림 넣기

- 콘티 화면은 컷 카드만: 머리(번호·컷 글·인물·샷·앵글·감정·생성 해상도) + 왼쪽 그림 칸 + 오른쪽 NovelAI 프롬프트(기본·캐릭터별, 늘 펼침, 칸별 복사·전체 복사)
- 그림 칸은 생성 해상도 비율(예: 1408×640이면 가로 칸). 그림이 없으면 레퍼런스 썸네일을 흐리게 + '그림 넣기'(누르기·끌어 놓기), 있으면 '그림 바꾸기'·×로 빼기, 원고가 바뀌면 주황 테두리 + '원고가 바뀜 · 확인'
- 머리 버튼: 작화 설정(서랍) · Claude로 다듬기 · 그림 여러 장 · 프롬프트 txt
- 뺀 것: 읽기 요약·연출 근거, 샷·앵글·길이 표(값 바꾸기), 오른쪽 전체 웹툰 미리보기와 다른 안 넘기기. 연출은 씬 글 `{…}`로만
- (추가) 포스타입 글 화면처럼: 카드 상자 → 컷 사이 얇은 구분선과 넓은 여백, 제목 32px + 진한 밑줄, 머리 버튼은 작은 글자 버튼(가는 세로선 구분), 컷 번호는 파란 작은 숫자, 컷 글 18px/1.75 보통 굵기, 프롬프트는 왼쪽 세로선 인용처럼 15px/1.75, 칸별 '복사'는 마우스를 올릴 때만, 그림 칸은 테두리 없는 회색 바탕. 본문 폭 880px
- (추가) 콘티에서 '원고가 바뀜' 표시(주황 테두리·확인 버튼) 제거. 그림 칸을 340px(최대 높이 520px)로 키우고 본문 폭 1000px, 900px 이하에선 그림이 폭 전체
- (추가) 콘티 작업 흐름: 위쪽 고정 컷 칸 줄(그림 있는 컷은 채움, 누르면 그 컷으로), '그림 없는 컷만' 거르기, '전체 복사'한 컷에 '복사됨' 표시 + 그 컷이 Ctrl+V 붙여 넣기 대상, 단축키 J·K(다음·이전 컷)·C(전체 복사), 모든 컷에 붙는 화풍 태그는 흐리게(복사엔 그대로), 자르기 설명은 '자르기' 표시 + 마우스 올리면 자세히
- (추가) 콘티는 컷마다 테두리 상자(카드)로만 구분(태그 칩·프롬프트 상자는 되돌림). 단축키 안내는 키 모양 상자(J K 이동 · C 복사 · Ctrl+V 붙여 넣기)
- (추가) 콘티 · 토스 스타일: 회색 바탕(#f2f4f6) + 흰 둥근 카드(20px, 테두리·그림자 없음), 큰 제목 + 친근한 한 줄("그림 5장만 더 넣으면 돼요") + 파란 진행 막대, 보조 버튼은 연파랑 알약(그림 여러 장 넣기·Claude로 다듬기)과 흰 알약(작화 설정·txt), 컷 번호는 둥근 칩(그림 있으면 ✓, 지금 컷은 파랑), '빈 컷만'은 토글 스위치, '프롬프트 복사' 알약(누르면 '✓ 복사했어요' 파랑), 프롬프트는 연회색 둥근 상자, 화면 아래 고정 주 버튼 '편집으로 넘어가기'. 다크 모드 토큰 포함
- (추가) 콘티 흑백 처리(강조는 검정·회색, 다크 모드에선 반전), 아래 고정 '편집으로 넘어가기' 버튼 제거

## 55. 첫 로딩: 학습 모델 지연 로딩

- 모델 7개(원본 약 4.2MB, gzip 약 1.2MB)를 페이지와 함께 바로 끼워 넣던 것을 `load` 뒤 한가할 때(requestIdleCallback) 중요한 순서로 하나씩 불러오게 바꿈: 샷 → 감정·강도 → 앵글 → 칸 길이 → 연출명 랭킹 → 묶음 판정 → 레퍼런스 글.
- 붙을 때마다 다시 계산(최대 7번)하던 것을 0.4초 모았다가 한 번만 계산.
- 측정(로컬, 10Mbps·40ms 제한, 3회): 첫 화면 그림(FCP) 약 230ms로 같음 · `load` 7.0s → 1.9s · 모델 다 붙기까지 7.1s → 7.5s. 모델이 붙기 전에는 규칙 판정으로 먼저 보이고, 붙으면 한 번 갱신.
- 빈 컷 4개(DN-06-117·118, DN-07-017, MD-08-028) 다시 자름: DN은 영문판 좌표 어긋남, MD는 칸 나누기 오류.

## 56. 내보내기 점검: PSD 글자 레이어 위치·크기

- PSD 말풍선·나레이션의 텍스트 레이어가 `<text>` 속성만 보고 만들어져, 편집 화면에서 옮긴 위치(translate)·키운 크기(나레이션·효과음 `.lsc` scale)·말풍선 변형이 빠졌음.
- 글자 묶음을 화면 밖 SVG에 잠깐 붙여 누적 변형(getCTM)을 재고, 크기는 글자 크기·행간·자간에 녹이고 회전만 변형으로 남김. 글자 미리보기 픽셀도 변형을 지닌 복제본으로 그림.
- 확인: 나레이션을 1.5배·(30,40) 옮긴 뒤 PSD를 읽어 보니 글자 크기 20.8→31.2, 기준점이 미리보기 픽셀 상자 가운데·아래와 맞음.
- 연출 문법({집중선}·{배경} 등)은 `sceneArt`→`renderSVG`를 거쳐 SVG·PSD·PNG·슬라이스에 그대로 들어감(문법 추가 전후 SVG 요소 수 증가 확인).

## 57. 실행 취소를 원고·콘티에도

- 편집 화면에만 있던 기록(씬 글·pageEdits·등록 이미지 자리·끝 전환)을 원고(쓰기)·콘티 화면에도 씀. 위 막대 오른쪽에 되돌리기/다시 실행 버튼(원고·콘티에서만 보임), Ctrl+Z · Ctrl+Shift+Z · Ctrl+Y.
- 글 칸 안에서 타자 중일 땐 브라우저 자체 실행 취소를 그대로 쓰고, 칸 밖에서 Ctrl+Z면 화면 기록을 되돌림. 쓰기 화면은 1.5초 안의 수정을 한 단계로 묶음.
- 대사 자동 나누기(splitMixed)는 나누기 직전 글을 따로 한 단계로 남겨 Ctrl+Z 한 번에 원래 줄로 돌아감.
- 콘티 그림 넣기·빼기도 기록(그림은 uid로 가리켜 되돌리면 같은 그림이 같은 컷에).
- 확인(Playwright): 원고 섞인 줄 → 나뉨 → Ctrl+Z 원래 한 줄 → Ctrl+Z 입력 전 → Ctrl+Shift+Z 다시. 콘티 그림 1장 넣기 → 되돌리기 0장 → 다시 1장. 편집 화면 기존 되돌리기 그대로.

## 58. 편집 화면 정리(1·2)

- 상황 막대에서 화면 배치 설정(미니맵·세로/나란히·작업 공간·배치 초기화)을 빼서 위 막대의 「보기」 메뉴 하나로. 상황 막대는 고른 도구·선택한 것 + 「속성」만.
- 톤: 레이어 선택 표시를 파랑 → 회색(씬·콘티와 같은 흑백), 버튼·레이어 줄 모서리 10px.
- 글자: 편집 화면 13px 미만 글자 52/102 → 0(레이어 줄·상황 막대·에셋 패널·저장 표시).
- 모바일(≤760px): 캔버스 먼저, 원고 폭에 맞춰 시작(fitWidth). 레이어는 위 막대 「레이어」 버튼으로 여는 아래 시트(컷을 누르면 닫힘). 위 막대는 가로 스크롤, 「편집 · 자동 저장」 글은 숨김.
- 모바일(≤640px) 머리: 단축키·테마·DB 버튼과 씬 이전/다음 화살표를 숨겨 「내보내기」가 잘리지 않게.

## 59. 캐릭터·세계관·구성 화면 톤 맞추기(4)

- 이미지 없는 대표 이미지 칸: 이름별 색(분홍·올리브 등) → 회색(--tb50) + 회색 첫 글자, 모서리 20px. 대사 옆 작은 얼굴칩은 인물 구분용이라 색 유지.
- 입력칸·버튼·세그먼트 모서리 12px(콘티 카드와 같게), 13px 미만 글자 캐릭터 10→0 · 세계관 11→0 · 씬 36→2.
- 씬 목록 선택 표시도 파랑 → 회색. 원고·콘티 위 막대의 되돌리기/다시 실행 버튼은 가로로.
- 구성→씬: 구성안 씬을 붙이기 전에 저장하던 순서를 바로잡아(붙인 뒤 저장) 새로고침해도 남게. 추가 뒤 씬 화면으로 넘어가며 안내 토스트.

## 60. 자동 칸은 늘 네모

- 자동으로 잡는 칸은 비율·크기(칸 길이 모델·이미지 비율)는 컷마다 다르게 두되 모양은 늘 네모. 전에는 고른 레퍼런스 컷이 사선 칸이면 그 꼭짓점을 따라 칸도 사선이 됐음.
- 칸 모양 바꾸기(편집 화면 꼭짓점 끌기, 저장된 quad, 시퀀스 템플릿)는 그대로. 레퍼런스 목록의 「사선 칸」 표시도 그대로(참고용).
- 확인: 예시 씬 1(사선 레퍼런스 1컷)의 자동 칸 다각형 0개, 꼭짓점을 직접 옮긴 컷은 사선으로 그려짐.

## 61. 에셋 패널: 타일이 실제 결과를 보여 줌(기획 1·2)

- 말풍선: 20px 아이콘 → 2열 큰 타일에 실제 말풍선 모양(presetBalloon) + 고른 컷의 대사(없으면 "대사").
- 효과음: 글자 버튼 → 편집 화면과 같은 레터링(soundEffectSVG, 소재 그림이 있으면 그 그림). 소재 묶음·즐겨찾기 효과음도 같은 타일.
- 효과선: 고른 컷 썸네일 위에 실제 집중선·속도선(원고 폭 630 기준으로 그려 굵기 비율 유지).
- 배경: 「위 컷 → 전환(흰색→중간색→시작색 + 질감 무늬) → 아래 컷」 세로 띠. 배경색은 컷 썸네일이 그 색 위에 놓인 모습 + 색 이름(검정·밤·분홍…).
- 추천: 카드 = 고른 컷에 넣은 모습 + 이유("설렘 1에 어울리는 전환 · 자동", "대사에 느낌표 · 센 강도 · 자동", "글에 쓴 효과음 · 자동"). 최근 쓴 것·★도 같은 미리보기.
- 전역 `.pv`(미리보기 패널, sticky)와 겹치지 않게 타일 클래스는 `apv`.

## 62. 효과음 타입·검색, 모든 에셋 즐겨찾기, 효과음 미리 불러오기

- 효과음 탭: 레터링 타입 4개(A 흰 테두리 · B 계단형 · C 가는 펜선 · D 컷 전 선행음)를 골라 그 타입 그림으로 타일을 보여 주고, 누르면 그 타입으로 넣음(letters[material-id].materialVariant). 고른 타입은 기억.
- 효과음 전용 검색(글자·분류) + 분류 고르기. 소재 615종을 전부 보여 줌(전에는 검색어가 있을 때 120개까지만). 자주 쓰는 낱말도 묶음에 있으면 묶음 그림(고른 타입)으로.
- 즐겨찾기: 모든 에셋 타일 오른쪽 위 ★(마우스를 올리면 보임, 터치 기기는 늘 보임). ★ 탭에 말풍선·효과음·효과선·배경·배경색·이미지/시퀀스로 나눠 모아 봄. 예전 효과음 즐겨찾기(rough-material-favorites)와 함께 씀.
- 처음부터 다 불러오기: 효과음 ZIP을 한 번 불러오면 브라우저(IndexedDB)에 남고, 이제 페이지가 뜬 뒤 한가할 때 615종 × 4타입 그림을 전부 미리 풀어 둠(40개씩). ZIP 자체는 사용자가 가져온 소재라 저장소에 넣지 않음.
- 확인(Playwright, 시험용 가짜 묶음): 새로고침 뒤 615종 미리 불러옴, C 타입으로 넣기 → materialVariant 'C', 검색 "두근" 1개, 말풍선·효과음 ★ → ★ 탭에 분류별로.
- (보완) 효과음 소재는 60개씩: 처음엔 첫 60개 + 자주 쓰는 낱말만 그림을 풀고, 목록 맨 아래가 보이면 다음 60개를 풀어 붙임(IntersectionObserver). 검색·분류·타입을 바꾸면 다시 60개부터. ★·추천에 있는 소재는 그것만 따로 풀어 그림. 확인: 시작 60 → 스크롤마다 120·180·240, 검색 결과 108개 중 60개 먼저.
- (보완) 효과음 소재 사이트 기본 묶음: 배포 허락을 받아 `rough/sfx/`(list.csv + png/번호/A~D.png)에 두면, 이 브라우저에 직접 불러온 ZIP이 없을 때 그걸 씀. 그림은 쓸 때 하나씩 받음(60개씩 스크롤 로딩 그대로). 넣는 법: `python3 tools/unpack_sfx.py 효과음.zip`. 시험용 묶음으로 새 브라우저에서 615종·첫 60개 확인(시험 파일은 커밋 안 함).
- (보완) 효과음 그림을 타입별로 따로 받음: 고른 타입 그림만 받고(첫 66개 기준 4타입 6.9MB → A 3.4 · B 2.0 · C 0.75 · D 0.8MB), 원고에 쓴 효과음도 그 컷에 쓴 타입만. 속성의 타입 바꾸기 버튼을 열 때만 네 타입을 다 받음.

## 63. 씬 화면 요소 다듬기 (레이아웃 그대로, 포스타입 에디터 기준)

- 「콘티 보기」 버튼은 뺌(위 단계 탭 「5 콘티」와 겹침). 검정 버튼은 머리의 「내보내기」만.
- 위 막대 왼쪽에 분량 한 칸: `6컷`(포스타입 `0자` 자리). 세로 길이·휴대폰 화면 수는 본문 통계에.
- 문법 버튼: 기호를 회색 키 칩(`[ ]` `@` `- -` `{ }`)으로, 글자는 진하게. 효과음 기호 `-♪-` → 실제 문법 `- -`.
- 오른쪽 칩의 `· 자동`/`· 내 취향` → 칩 끝 옅은 꼬리표(세로줄 + 옅은 글자), 자동 칩은 점선 테두리. 글에 직접 적은 값은 꼬리표 없이 실선.
- 씬 목록 삭제 `−` → 휴지통 아이콘(마우스를 올리거나 고른 씬에서만, 터치 기기는 늘). 「예시 씬 추가」는 버튼 → 글 링크. 「이 씬 모두 지우기」는 휴지통 + 옅은 글(올리면 빨강).
- 단축키: Ctrl+S(눌러도 "저장됨 · 방금" 표시, 자동 저장은 그대로), 컷 글 칸에서 Ctrl+Shift+↑/↓로 컷 순서 바꾸기(커서 위치 유지, Ctrl+Z로 되돌림).
- 휴대폰: 씬 목록을 가로 칩 한 줄, 「+ 새 씬」·「예시 씬 추가」를 한 줄, 통계는 가로 스크롤 한 줄 → 첫 컷 글 위치 605 → 486px(화면 688).

## 64. 콘티 화면 버튼 정리

- 버튼은 「작화 설정」 · 「Claude로 다듬기」 둘만, 화면 맨 위(제목 위)에 작화 설정 먼저.

## 65. 콘티: 작화 설정을 맨 위에 늘 펼침 + 프롬프트 생성 두 개

- 작화 설정(서랍) → 콘티 맨 위 카드, 늘 펼침. 위계: 작화 설정 카드(제목 22px, 「작품 전체」 꼬리표) > 씬 머리(「이 씬」) > 컷 카드.
  - ① 화풍 태그(넓은 입력칸 16px) ② 인물 태그(얼굴칩 · 이름 · 입력칸 · 「외형에서 다시」). 레퍼런스·장면 이미지 요약, 모델·키 줄은 뺌.
  - 출처 꼬리표: 화풍 `기본`(점선)·`생성`, 인물 `자동`(외형 규칙, 점선)·`생성`(Claude)·꼬리표 없음(직접 고침). 기록: localStorage `rough-art-gen`.
- 버튼 둘:
  - 「작화 프롬프트 생성」(작화 설정 카드): 세계관 + 인물(이름·성별·외형·지금 태그) → Claude(claude.js `genArt`) → 화풍 태그 + 인물 외형 태그. 바로 덮지 않고 비교 창(지금 취소선 / 제안)에서 체크한 것만 적용. 직접 고친 값은 체크 해제로 시작. 인원 태그(1girl 등)는 컷 프롬프트가 붙이므로 넣지 않게 함.
  - 「컷 프롬프트 생성」(씬 머리): 예전 「Claude로 다듬기」 이름만 바꿈(씬 컷마다 태그·인물 위치). 화풍이 기본값이고 생성한 것도 없으면 "작화 프롬프트를 먼저 만들면…" 안내.
- 「프롬프트 저장」(씬 머리 글 링크): 설명 없이 프롬프트만. 컷 하나 = 기본 + 인물 프롬프트(빈 줄), 컷 사이 빈 줄 두 개. 복사·저장 모두 같은 태그가 두 번이면 한 번만.
- 실제 Claude 호출은 API 키가 없어 이 환경에서 시험 못 함(비교 창·적용·저장은 가짜 응답으로 확인).

## 66. 말풍선·나레이션: 더블클릭으로 바로 글자 고치기 · 네 방향으로 상자 늘리기

- 한 번 누르면 선택 상자에 손잡이 8개: 모서리 4개는 전체 크기(기존, 글자도 함께), **변 4개(위·아래·왼쪽·오른쪽)는 상자 가로·세로만**(글자 크기 그대로). 끄는 쪽 변만 움직이고 반대쪽은 제자리(위치를 함께 옮김). 효과음에는 변 손잡이 없음.
  - 저장: letters[key].bw / .bh(늘린 px, 음수면 줄임, -40~600). 말풍선은 rx·ry에, 나레이션 상자는 폭·높이에 더하고 글자는 가운데 유지.
- 두 번 누르면 그 자리에 글 상자가 떠서 바로 고침: Enter 줄바꿈 · Ctrl+Enter 또는 바깥 클릭 저장 · Esc 취소 · Ctrl+Z 되돌리기. 끌기 겹(DIV)이 놓을 때 대상을 가져가 dblclick이 식자로 안 와서, 누를 때 대상으로 두 번 누름을 판별.

## 67. 식자 글꼴 고르기 (DB 컷 기준 5종)

- DB 글 칸(상세 식자와 효과)에는 글꼴 기록이 거의 없어(1,799개 중 손글씨 1·굵은 2), 작품별 말풍선 16장씩(DN·GM·HC·HN·MD, 80장)을 잘라 직접 봄.
  - DN·MD: 보통 굵기 둥근 고딕 / GM·HC: 좁고 조금 굵은 고딕(색 글자도) / HN: 바탕(명조) 계열 / 외침·효과: 아주 굵게 / 손글씨는 짧은 혼잣말·효과에 드물게
- 고를 수 있는 5종(모두 OFL 웹 글꼴, jsDelivr에서 쓰는 글자 조각만 받음 — CSP가 이미 허용):
  기본 고딕(Pretendard 500) · 좁은 고딕(Pretendard 600, 자간 좁게) · 바탕(Gowun Batang 700) · 굵은 강조(Pretendard 800) · 손글씨(Nanum Pen Script, 1.4배)
- 고르는 곳: 말풍선·나레이션을 고르면 상황 막대에 「글꼴」(작품 기본 + 5종, 목록에서 미리 그 글꼴로 보임). 작품 전체 기본은 속성 서랍 › 글자 「작품 기본 글꼴」(자동 = 말풍선 모양 따라 굵기).
  - 저장: letters[key].font, 작품 기본은 localStorage `rough-page-preset`. 직접 고른 글꼴의 굵기가 우선, 자동일 때는 외침·강도에 따른 굵기 유지.
- PSD 글자 레이어는 그 글자에 쓴 글꼴 이름으로 들어감.
- 남은 것: PNG·연재용 분할 내보내기는 SVG를 그림으로 바꾸는 방식이라 웹 글꼴을 못 써서 시스템 글꼴로 나옴(기존 한계). 글꼴 파일을 내보낼 때 넣으면 해결되지만 한글 글꼴이 커서(글꼴당 수 MB) 따로 정해야 함.
- (수정) 글꼴은 3종만: 좁은 고딕 · 바탕 · 손글씨. **모든 글씨 기본은 바탕**(작품 기본 「자동」 없앰, 예전에 고른 기본 고딕·굵은 강조는 바탕으로). 말풍선 하나만 다른 글꼴이면 상황 막대 「글꼴」에서.
- (수정) 기본 말풍선 모양을 DB에서 가장 많이 쓰인 모양으로: 흰 바탕 · 검은 실선(2.2) · 매끈한 타원 · 가는 꼬리. 예전 기본(크림색 바탕, 손으로 그린 듯 흔들리는 테두리, 어긋난 보조선)은 지움. 외침(뾰족)·생각(구름) 같은 자동 모양과 말풍선 형태 목록은 그대로.

## 68. 글자 꾸밈 도구 · 나레이션 기본 형태

- 말풍선·나레이션을 고르면 상황 막대에 포스타입 에디터처럼 아이콘 도구:
  - 글꼴: 「가 가 가」 세 칸(좁은 고딕 · 바탕 · 손글씨를 그 글꼴로 보여 줌, 지금 쓰는 것이 검정)
  - 굵게 B · 기울임 I · 밑줄 U(Ctrl+B / I / U), 글자색 A(아래 색 막대가 지금 색). 누르면 색 10개(DB 컷에서 본 글자색: 검정·흰색·회색·초록·파랑·보라·빨강·주황·갈색·분홍) + 직접 고르기.
  - 저장: letters[key].font / bold / italic / underline / color. 굵게 끄면 글꼴 기본 굵기(바탕 400 · 좁은 고딕 600), 켜면 바탕 700 · 좁은 고딕 800.
- 나레이션 기본: DB 나레이션 컷 471개(HN 199 · MD 111 · DN 87 · GM 44 · HC 30)를 작품별로 보니 상자 없이 글자만 가운데가 대부분(HN·MD·DN). 상자는 GM(장식 테두리)·HC(얇은 실선) 일부뿐.
  → 기본을 「상자 없이 글자만」으로. 그림 위에서도 읽히게 글자색과 반대 톤 테두리를 얇게(검정 글자면 흰 테두리, 밝은 글자면 검정 테두리). 예전 자동 상자(초록 장식 상자 · 회갈색 반투명 상자)는 지움. 흰 사각 상자는 형태 「나레이션 · 사각」으로 그대로.
- (추가) 글자 테두리색: 글자색 A 옆에 테두리 A 버튼. 색 9개 + 「없음」 + 직접 고르기. 저장 letters[key].outline(색 또는 'none'). 비워 두면 나레이션은 자동(글자와 반대 톤), 말풍선은 테두리 없음. 나레이션만 있는 컷처럼 어두운 그림 위 글자는 흰 글자 + 원하는 테두리색으로.

## 69. 레이어 패널 「칸」·「그림」 고르기

- 패널 줄은 골라졌지만 캔버스에서는 칸이든 그림이든 똑같이 그림 확대 손잡이가 떠서 무엇을 골랐는지 안 보였고, 캔버스를 누르면 바로 풀렸음.
- 고침: 「칸」 → 그림 손잡이를 숨기고 칸 테두리(크기·모양) 손잡이만. 「그림」 → 그림 확대 손잡이. 캔버스에서 컷 그림을 누르면 패널의 그 컷 「그림」 줄이 골라짐(식자·간격·빈 곳을 누르면 풀림). 고른 줄은 회색 + 왼쪽 막대.
- Delete: 「그림」 줄을 고른 채면 넣은 그림만 빼고(기존), 「칸」이면 컷 지우기(기존).

## 70. 편집 조작 보강 (docs/edit-interaction-research.md 「바로·다음·그다음」 전부)

새 파일 `rough/edit-plus.js`(workspace.js 내부 함수는 `RoughWS`로 내보내 씀) + index.html 끌기 코드 · letterSVG.
- **복사·붙여넣기·복제(식자):** Ctrl+C / V / D. 형태·크기·글꼴·꾸밈·늘린 상자·회전·꼬리 그대로. 같은 컷이면 20px씩 비켜, 다른 컷을 고르고 붙이면 그 컷의 같은 상대 위치에. 컷 글에 대사·나레이션·효과음 줄이 더해짐(효과음 소재는 소재 목록에). 우클릭 메뉴에도.

- **여러 개 함께 끌기:** 고른 식자 전부(다른 컷 것도) 같은 만큼.
- **맞춤선:** 끄는 식자의 왼쪽·가운데·오른쪽/위·가운데·아래가 컷 가운데·좌우 여백(24)·같은 컷 다른 식자 가장자리·가운데에 5px 안이면 붙고 분홍 선. Ctrl(⌘) 누르면 끔.
- **Alt+끌기:** 옮긴 것은 그대로, 원래 자리에 복제본.
- **사각형 고르기:** 캔버스 빈 곳이나 컷 그림 위(확대한 그림·그림 편집 중 제외)에서 끌면 걸친 식자 전부. Shift면 더하기.

- **회전:** 선택 상자 위 동그란 손잡이(말풍선·나레이션·효과음). Shift 15° 단위, 2° 안은 0으로. 저장 letters[key].rot(도), 우클릭 「회전 없애기」.

- **레이어 패널 끌기:** 컷 줄을 끌어 같은 씬 안 순서 바꾸기(그림·편집값 함께), 식자 줄을 끌어 같은 컷 안 겹침 순서(아래 줄일수록 앞).
- 단축키 창(?)에 모두 추가.
- 확인(Playwright): 붙여넣기 +1 · 복제 +1(Ctrl+Z로 되돌림) · Shift+끌기 가로만(dy 0) · 여러 개 끌기 둘 다 (38,19) · 맞춤선 1개 · Ctrl+A 2개(글자 선택 0) · 사각형 2개 · 맨 뒤로 순서 바뀜 · 회전 67° · Enter 편집 상자 · Tab 다음 식자 · Alt+끌기 +1 · 패널에서 1컷을 3번째로.
- (보완) 레이어 패널에서 식자·칸·그림 줄을 누르면 그 요소를 화면 가운데로(위 고정 막대 높이를 뺀 가운데, 캔버스가 넓으면 가로도). 컷 고르기 스크롤이 늦게 끝나 식자가 화면 밖에 남던 것 → 끝난 뒤 한 번 더 맞춤. 확인: 2씬 5·6컷, 1씬 6컷 식자 모두 화면 안.

### 71. 컷 모퉁이 확대·축소 · 더블클릭 프레임 모양 · 넣기 도구로 식자 누르면 고르기 (2026-11-24)
- 컷을 고른 뒤 모퉁이를 끌면 컷 전체가 비율대로 커지고 작아진다(맞은편 모퉁이 고정, 사선 모양도 같은 비율로).
- 컷을 더블클릭하면 「프레임 모양」 모드: 모퉁이가 파란 동그라미로 바뀌고 하나씩 끌어 사선 칸을 만든다. 다시 더블클릭 · Esc · 다른 컷 고르기로 끝.
- 검은 안내: 고른 컷 위에서 「더블클릭하면 프레임 모양을 바꿀 수 있어요」, 모드 중엔 「모퉁이를 하나씩 끌어 프레임 모양을 바꿔요 · Esc 끝내기」.
- 그림 확대·이동은 상황 막대 「그림 편집」 · 레이어 「그림」 더블클릭으로 옮김. 캔버스에서 컷을 누르면 레이어 「칸」이 골라짐.
- 식자 선택 상자의 변 가운데 둥근 손잡이 제거(모서리 크기 · 위 회전 손잡이는 유지).
- 말풍선·나레이션·효과음 도구를 든 채 이미 있는 식자를 누르면 새로 넣지 않고 선택 도구로 바뀌며 그 식자를 고른다(Alt 누르면 예전처럼 위에 넣기).
- 첫 클릭에 화면이 다시 그려져 브라우저 dblclick 대상이 사라지므로, 누름 두 번(420ms · 6px 안)을 직접 잰다.

### 72. 레이어 패널 ↔ 캔버스 선택 연동 점검 · 회전 손잡이 잘 보이게 (2026-11-24)
- 점검(Playwright): 캔버스 식자·컷 클릭 → 패널 표시, 패널 컷·칸·그림·식자 클릭 → 캔버스 선택·이동은 맞음.
- 어긋나던 것 3가지 고침:
  1. 고른 줄이 패널 스크롤 밖이면 안 보임(컷이 많을 때) → 패널을 굴려 고른 줄을 보이게.
  2. Shift·사각형·Ctrl+A로 여러 개 고르면 패널엔 하나만 표시 → 고른 식자 전부 표시, 풀면 같이 풀림.
  3. 패널에서 접어 둔 컷의 식자를 캔버스에서 고르면 패널에 안 나옴 → 자동으로 펼침.
- 회전 손잡이: 14px 흰 동그라미라 컷 테두리·간격 손잡이와 같은 모양이어서 묻혔음 → 22px 파란 원 + 흰 회전 화살표 + 그림자, 줄기 22px로 위로 더 띄움.

### 73. 편집 화면 렉 줄이기 (2026-11-24)
- 측정(Playwright + CPU 프로파일, 예시 원고 2씬 12컷):
  - 레이어 패널 다시 그리기 270ms/회 — `scenePanels()`가 부를 때마다 연출 엔진(분석 + 레퍼런스 고르기 `suggestRef`)을 처음부터 다시 돌림. 패널은 컷마다 불러 12번.
  - 식자 클릭마다 에셋·레퍼런스 패널을 즉시 다시 그림(70ms).
- 고침:
  1. 다른 씬 컷 계산 캐시: 글·고른 레퍼런스·고정값·인물·DB 크기가 같으면 이전 결과 재사용.

### 75. 편집툴 개선 묶음: 글에 맞추기 · 휴대폰 화면 선 · 프레임 기울기 · 처음 안내 · 회차 · 터치 · 손잡이 (2026-11-24)
- **글에 맞추기**: 말풍선·나레이션을 고르면 상황 막대 「글에 맞추기」(여러 개 골라도 됨) → 늘리거나 줄인 상자(bw·bh)를 없앰. 상자를 아무리 줄여도 글이 밖으로 넘치지 않게 글 크기 + 여백을 최소로 둠.
- **휴대폰 한 화면 선**: 보기 › 「휴대폰 한 화면 선」 또는 Shift+G. 원고 폭 × 1.9(390×740 보이는 영역)마다 분홍 점선과 「N화면」 표시, 씬을 건너 이어서 셈. 확대·다시 그리기에 맞춰 다시 계산.
- **프레임 모양 수치**: 컷을 고르면 상황 막대 「프레임 모양」(컷 더블클릭과 같음). 켜면 위·아래 기울기(°, −30~30, 양수 = 오른쪽이 내려감)와 프리셋 네모·위 사선·아래 사선·평행 사선·쐐기. 모퉁이를 안쪽으로만 옮겨 이웃 칸을 침범하지 않음.
- **처음 안내**: 편집 화면·컷 고르기·식자 고르기를 처음 할 때 한 번씩 짧은 말풍선(고른 것 옆에 떠서 손잡이를 가리지 않음, 아무 데나 누르면 닫힘). 보기 › 「처음 안내 다시 보기」.
- **회차 관리**(`episodes.js`): 위 막대 「1화 ▾」 → 회차 바꾸기·새 회차(빈 원고)·이 회차 복제(넣은 그림까지)·이름 바꾸기·순서·지우기. 회차마다 씬·구성을 따로 저장(`rough-ep:<id>:<칸>`), 인물·세계관·작화 설정·글꼴은 모든 회차가 같이 씀. 바꿀 때 저장 후 새로 불러옴(실행 취소 기록은 회차마다 새로 시작).
- **터치·펜**: 두 손가락 벌리기 = 캔버스 확대(브라우저 화면 확대 막음), 길게 누르기(0.55초) = 우클릭 메뉴, 두 번 탭 = 프레임 모양. 손가락으로 식자·컷 모퉁이를 끌면 스크롤로 넘어가 끊기던 문제 수정(SVG 안쪽은 touch-action이 안 먹어 touchstart에서 막음). 빈 곳·그림을 한 손가락으로 끌면 스크롤(사각형 고르기는 마우스·펜만). 손가락 기기에선 손잡이·버튼을 크게.
- **손잡이**: 미니맵에 편집 손잡이·고른 표시·안내선을 옮기지 않음. 회전 손잡이가 컷 위 테두리·간격 손잡이·위 고정 막대에 겹치면 상자 아래(꼬리 손잡이를 피해 오른쪽으로 비켜서)로.
- 검사(Playwright): 위 항목 모두 실제 조작으로 확인, 이전 기능(패널 연동·프레임·회전·에셋) 회귀 없음, 70컷 성능 변화 없음.

- **내보내기 확인**(회전 −12° · 손글씨 · 빨간 테두리 · 파란 글자 · 줄인 상자 · 사선 칸으로 실제 내보내 봄):

- **스타일 적용 ▾**(말풍선·나레이션 상황 막대): 고른 것의 모양·글꼴·굵게·기울임·밑줄·색·테두리·크기를 고른 식자 전부 / 같은 인물 대사 전부 / 이 씬 / 모든 씬에. 위치·문구·늘린 상자는 그대로. 대사에 말한 인물(data-who)을 붙임.
- **버전 비교**: 이전 버전 창에 「비교」(그때 ↔ 지금 나란히, 스크롤 맞춤, 글이 바뀐 컷 목록: 추가·삭제·수정·배치), 「지금 버전 남기기」(이름 붙여), 되돌리기 전 지금 상태 자동 기록. 기록을 회차별로 나눔(다른 회차 원고로 되돌아가던 위험 제거). 보기 › 「이전 버전 · 비교」.
- **컷 단위 다시 그리기**: 씬 안에서도 SVG 바로 아래 요소(컷 묶음·배경·간격)를 견줘 바뀐 것만 교체. 씬 계산 캐시 키가 편집값 배열 길이만 늘어도 바뀌던 문제 수정 → 70컷 기준 컷 모퉁이 놓기 87→0ms(멈춤 없음). 말풍선 넣기는 글이 바뀌어 그 씬 연출 계산(약 60ms)이 필요해 0.15초 남음.
- **간격 일괄 ▾**(컷 상황 막대): 입력한 아래 간격을 이 씬/모든 씬 모든 컷에, 또는 기본(자동)으로. (같은 이름 함수가 간격 우클릭 메뉴를 덮어쓸 뻔한 것 바로잡음)
- **말풍선 읽는 순서**(보기 메뉴): 대사마다 글 순서 번호, 화면 위치(위→아래, 같은 높이면 왼→오)로 읽히는 순서와 다르면 빨간 번호와 「→실제 순서」. 나레이션은 기본 자리가 컷 아래라 제외.
- **회차 썸네일·표지**: 회차 메뉴에 썸네일·씬/컷 수, 「고른 컷을 이 회차 표지로」, 회차 버튼에 표지 썸네일.
- **버그**: 편집 화면에서 컷을 고른 채 새로고침하면 가끔 상황 막대가 아직 없는 입력칸을 읽다 멈추고 편집기 전체가 안 되던 문제(배포본에도 있었음) → 상황 막대 그리기를 안전하게.

### 78. 말풍선 꼬리 테두리 굵기 맞춤 (2026-11-25)
- 원인: 몸통은 테두리를 그린 뒤 이음새를 지우려 몸통 면(cover)을 한 번 더 덮어 테두리 안쪽 절반이 가려짐 → 보이는 굵기 ≈ 1.1. 꼬리는 2로 긋고 덮지 않아 다 보임 → 몸통의 약 두 배.

- 바탕 회색 + 흰 둥근 카드, 번호 단계(콘티 「작화 설정」과 같은 결). 머리줄에 「구성안 · 이 회차」 배지, 웹툰/마케팅, 「구성안 생성」(오른쪽 위). API 키가 있으면 키 줄은 숨김.

- 결과: 「이번 화 구성」 + 씬·컷·잠금 수, 요약, 씬별 컷 비율 막대, 씬 바로가기 칩. 씬 카드는 번호 · 제목(바로 고침) · 컷 수 · 잠그기/다시 생성, 역할·감정 변화·마지막 컷 3칸, 컷 초안은 번호 목록(처음 4컷, 더 보기). 잠긴 카드는 회색. 「씬으로 보내기 →」는 아래에 떠 있는 버튼.
- 저장 형식·생성 로직(composition.js)은 그대로, 같은 입력 이름을 써서 기존 저장값이 그대로 열림. 모바일 폭 확인.

### 80. 구성안 「분량」 → 「한 화 분량」(리서치 기반) (2026-11-25)
- 근거: `docs/webtoon-episode-planning.md`(웹 자료 + DB 44화 실측). 현장 단위는 컷(계약·원고료), 씬 수는 결과로 나오는 값. 실측 중앙값 그림 컷 80 · 씬 7 · 씬당 11컷 · 휴대폰 약 85화면, 1화는 약 1.2배, 콜드 오픈 72%, 강도 최고점은 마지막 10%, 마지막 컷 91%가 '공개'.
- 화면: 회차 칩(1화 100컷 · 일반 75 · 짧은 회차 40으로 시작값) → 컷 수(주 입력) · 씬 수(기본 자동) → 예상(씬·씬당 컷·휴대폰 화면·말풍선) 즉시 표시 → 한 화 뼈대 막대(오프닝 · 전개 · 고조 · 엔딩 훅 컷 수) → 시작 방식(콜드 오픈/타이틀부터).
- Claude: 컷 수를 목표 합계로, 씬 수는 자동이면 컷/15~컷/8 범위. `config.structure`(회차 종류·콜드 오픈·오프닝/엔딩 컷 수)와 규칙(첫 씬 = 타이틀 앞 도입, 1화는 소개 압축, 마지막 씬이 가장 길게, 강도 최고점 마지막 10%, 마지막 컷은 엔딩 방식에 맞는 공개)을 전달.
- 결과 머리줄에 휴대폰 화면 수. 마케팅 모드는 섹션 수 입력 그대로.

### 81. 구성안 회차 종류에 「4~6컷 만화」 추가 (2026-11-25)

### 82. 구성안으로 만든 컷이 길쭉하던 문제 (2026-11-25)
- 진단: 프롬프트가 아니라 칸 길이 예측 모델(ML②)의 입력 분포 차이. 모델이 「컷 설명 글 길이」에 가장 큰 가중치(1.70, log 높이)를 주는데, 학습 DB의 설명은 짧은 메모(중앙 25자)이고 Claude가 쓴 컷 글은 더 자세함 → 구성안 스타일 12컷 높이 중앙 2.01(절반이 상한 근처), 예시 씬 0.97, 실제 연재작 1.19. 대사 수 가중치(0.78)도 같이 키움.
- 고침(engine.js): ① 글 길이를 씬 안 상대 길이로(씬 중앙 길이를 DB 중앙 25자에 맞춤) ② 묶음 전체 예측 중앙값이 1.25를 넘으면 1.25로 눌러 맞춤(컷끼리 길고 짧음은 유지). 결과: 같은 12컷 중앙 1.25(0.6~2.23), 예시 씬 변화 없음, 엔진 테스트 전부 통과.
- 프롬프트(composition.js): 컷 첫 줄은 그림에 보이는 것만 한 문장(40자 안팎), 심리 설명·여러 동작 나열 피하기.

### 86. 구성안 씬 카드 아래(컷 초안) 재구성 (2026-11-25)
- 「컷 초안 · N컷 · 누르면 바로 고쳐요」 소제목 아래, 컷마다 왼쪽 「N컷」 이름표 + 흰 둥근 상자.
- 상자 안은 씬 화면과 같은 문법으로 보여 줌: 행동 글은 본문, @인물은 강조색, 대사는 인물 이름표 + 옅은 말 상자, [나레이션]은 왼쪽 선이 있는 옅은 상자, -효과음-은 빨간 굵은 글씨.
- 상자를 누르면(또는 Enter) 그 자리에서 글칸으로 바뀌어 고치고, 벗어나면(Esc) 다시 보기 모양. 잠긴 카드는 고칠 수 없음.
- 「컷 N개 더 보기 ↓ / 접기 ↑」는 점선 테두리의 넓은 버튼.

### 87. 레이어 패널 여러 개 고르기(식자 → 컷 단위) (2026-11-25)
- 레이어 패널에서 Ctrl(⌘)+클릭 = 하나씩 더하기·빼기, Shift+클릭 = 범위(패널 순서, 씬을 넘어도 됨). 그냥 클릭·캔버스 클릭·Esc = 풀기.
- 같은 컷 안의 식자끼리면 지금처럼 식자 여러 개(정렬·스타일 적용 등). 다른 컷의 줄을 더하거나 컷 줄을 고르면 그 순간 「컷 여러 개」로 바뀜(요소가 아니라 컷을 잡음).
- 컷 여러 개: 패널 컷 줄 파란 배경, 캔버스 칸 테두리 파랑. 위 막대 「컷 N개」 — 아래 간격 적용 · 빈 컷 · 프레임 초기화 · 잠그기/풀기 · 컷 지우기(확인 후, Delete 키도) · 선택 풀기. 잠긴 컷은 건너뜀, 모두 Ctrl+Z로 되돌림.

### 88. 편집 레이어 패널: 씬 고르기 · 씬 지우기 (2026-11-25)
- 레이어 패널의 씬 제목 줄을 누르면 그 씬을 고름(패널 줄 파란 배경, 캔버스 씬 테두리 파랑, 위 막대 「씬 N · 제목 · N컷 · 씬 지우기」). Delete(Backspace) 또는 「씬 지우기」 → 확인 후 지움. 씬이 하나뿐이면 지우지 않음. Esc·컷/식자/캔버스 클릭으로 풀림.
- 실행 취소가 씬 목록(추가·삭제·순서)까지 기록하도록 확장: 기록에 씬 id·나머지 속성을 넣고, 되돌릴 때 목록이 다르면 목록부터 맞춤 → 지운 씬도 Ctrl+Z로 되살아나고 Ctrl+Shift+Z로 다시 지워짐.

### 89. 에셋: 같은 종류를 고른 상태에서 누르면 추가 대신 바꾸기 (2026-11-25)
- 효과음: 효과음(글에서 온 -쾅- 또는 소재 효과음)을 고른 채 에셋 패널·소재 패널의 다른 효과음을 누르면 새로 넣지 않고 그 효과음을 바꿈. 위치·크기·회전 유지, 소재 타입(A~D)은 지금 탭 타입으로. 글에서 온 효과음은 컷 글의 그 낱말을 바꿈(-똑똑- → -쾅-). 고른 효과음이 없으면 예전처럼 추가, 다른 컷에 끌어다 놓으면 추가.
- 말풍선: 고른 말풍선 + 말풍선 형태 누르기 = 형태 바꾸기(기존 동작 유지).
- 효과선: 컷에 다른 종류 효과선이 하나 있으면 집중선 ↔ 속도선으로 종류만 바꿈(위치·색·밀도 유지), 없으면 그리기 도구.
- 배경 전환·배경색·배경 이미지·컷 참고는 원래 컷당 하나라 바꾸기로 동작. 모두 Ctrl+Z로 되돌림.

### 90. 효과음·효과선 색 바꾸기 (2026-11-25)
- 효과음: 고르면 상황 막대에 「● 색」. 글자색과 같은 팔레트(+직접 고르기). 소재 효과음 그림은 SVG 색 필터로 어두운 획만 고른 색, 흰 테두리는 흰색 그대로(밝기 비례 섞기) · 글자로 그린 효과음은 글자 색. 검정(기본)을 고르면 처음대로. 편집 화면·PNG·PSD·SVG 내보내기 모두 같은 색.
- 효과선: 효과선이 있는 컷을 고르면 상황 막대에 「● 효과선 색」(속성 서랍 안에만 있던 색을 꺼냄). 그 컷의 효과선 전부 색 바꿈.
- 둘 다 Ctrl+Z로 되돌림.

### 91. 컷 사이 여백을 끌 때 선택 모두 풀기 (2026-11-25)
- 여백 손잡이를 누르는 순간 고른 식자·여러 식자·컷·여러 컷·씬·그림 편집·프레임 모양을 모두 풀고(손잡이·선택 상자·상황 막대가 가리지 않게) 여백만 조절. 레이어 패널 표시도 같이 풀림. `clearAllSelection()`.

### 92. 말풍선 넣기·고치기 한 자리: 1~3단계 (2026-11-25, 기획 docs/balloon-edit-plan.md)
- **1. 튐 고치기:** 에셋에서 말풍선을 넣은 뒤 화면 맨 위 속성 서랍을 자동으로 열지 않음, 커서는 `preventScroll`. 편집 알림(#wst)을 줄을 차지하지 않는 떠 있는 알림으로(4초 뒤 흐려짐) → 넣을 때 페이지·패널 스크롤 변화 0px.
- **2. 편집 카드(letter-card.js):** 오른쪽 패널(에셋 자리) 맨 위에 붙는 카드. 고른 식자가 있을 때만 보임. 에셋에서 넣은 직후·상황 막대 「문구 고치기」·Enter가 모두 카드 문구 칸으로. 문구는 0.3초 묶어 바로 반영(글자 수·줄 수, 작성 문구로), 글자(글꼴 3 · B I U · 글자색 · 테두리색), 형태(그림 격자), 크기 · 글에 맞추기, 꼬리 표시 · 방향 처음대로 · 두 칸 연결, 배치(컷 왼·가운데·오른, 회전 없애기), ⋯(스타일 적용 · 복제 · 잠금 · 지우기), ×(선택 풀기). 카드 버튼은 포커스를 가져가지 않아 타자 중에도 바로 눌림. 상황 막대는 「종류 · 문구 · 문구 고치기 · 스타일 적용 · 잠그기」로 줄임. 더블클릭 인라인 수정은 그대로.
- **3. 나레이션·효과음 카드:** 나레이션 = 글자 · 상자(글만/사각) · 크기 · 배치, 효과음 = 색 · 타입 A~D · 크기 · 배치.

### 93. 말풍선 넣기·고치기 4단계: 화자 바꾸기 · 나누기 제안 · 빈자리 배치 (2026-11-25)
- **화자 바꾸기:** 카드 머리의 「@준 ▾」 → 인물 목록 · 화자 없이 · 나레이션으로 바꾸기 · 속마음(점선 말풍선). 나레이션 카드는 「@인물의 대사로 바꾸기」. 컷 글의 그 줄을 고쳐 씬 화면과도 같음.
- **나누기 제안:** 대사가 32자를 넘으면 문구 칸 아래 「N자 · 두 말풍선으로 나누기」 → 가운데에 가까운 문장 끝(. ? ! … ,)에서 둘로, 같은 화자로 두 줄.
- **빈자리 배치:** 에셋을 눌러 넣을 때(끌어 놓기는 놓은 자리) 컷 안 3×4 후보 중 기존 식자와 가장 덜 겹치고 화면에 보이는 자리, 실제 크기로 계산. 그래도 화면 밖이면 캔버스만 부드럽게 이동. 컷을 고르지 않았으면 화면 가운데 컷에 넣음.
- 카드 문구 칸에 커서가 있어도 Ctrl+Z / Ctrl+Shift+Z는 (반영 안 한 타자가 없으면) 작업 전체 되돌리기. 카드가 툴바 아래에 살짝 띄워 붙음.

### 94. Esc = 고른 것 모두 풀기 (2026-11-25)
- 편집 화면에서 Esc를 누르면 고른 식자·여러 식자·컷·여러 컷·씬·그림 편집·프레임 모양을 모두 풀고 편집 카드도 닫힘(`clearAllSelection`).

### 95. 편집 카드 옮기기 (2026-11-25)
- 카드 머리줄(「말풍선 · N컷」)을 끌면 오른쪽 패널에서 떼어져 화면 아무 데나 둘 수 있음. 자리·폭을 기억(새로고침해도 그 자리), 다른 식자를 골라도 같은 자리. 머리줄의 ⇲ 또는 머리줄 더블클릭으로 다시 오른쪽 패널에 붙임. 떼어 둔 상태에서도 모든 버튼·문구 입력 동작.

### 96. 효과선이 클릭만으로 들어가던 문제 · 넣는 경로를 하나로 (2026-11-25)
- **원인(재현):** 효과선을 넣을 준비(집중선·속도선 도구)를 한 번 켜면 효과선을 넣은 뒤에도 도구가 「집중선/속도선」으로 남아, 이후 컷을 고르려고 누를 때마다 그 자리에 효과선이 또 들어감(세 컷 연속 들어감 확인). 도구가 켜지는 경로: ① 왼쪽 도구 막대 집중선·속도선(단축키 L·J) ② 에셋 「효과선」 탭 ③ 에셋 「추천」의 집중선·속도선 카드(감정 센 컷·빠른 동작 글) ④ 에셋 검색 결과 ⑤ 소재 패널 효과선 ⑥ 컷 우클릭 「효과선」 ⑦ 속성 서랍 「집중선·속도선」 버튼 ⑧ 효과선 에셋을 컷에 끌어 놓기(바로 넣지 않고 도구만 켬).
- **고침:** 효과선은 한 번 넣으면 선택 도구로 돌아감(한 번 쓰는 도구).
- **경로 하나로:** 효과선 = 왼쪽 도구 막대에서만(②~⑧ 제거, 속성 서랍에는 색·밀도·지우기 편집만 남김). 말풍선 = 오른쪽 에셋 패널에서만(왼쪽 도구 막대 말풍선 도구·단축키 B·소재 패널 말풍선·컷 우클릭 「여기에 말풍선」 제거). 처음 안내 문구도 맞춤.

### 97. 레이어 패널에 효과선·배경·이미지 소재 줄 (2026-11-25)
- 원인: 레이어 패널이 컷마다 「칸 · 그림 · 식자(말풍선·나레이션·효과음)」만 그렸음. 컷 편집값에 붙는 효과선(materialLines) · 배경(전환 질감·배경색·배경 이미지) · 이미지 소재(overlays)는 줄이 없었음.
- 고침: 컷을 펼치면 「◐ 배경(전환 질감·배경색·배경 이미지)」 「✳ 집중선/속도선」 「▣ 이미지 소재 N」 줄이 생김. 누르면 그 컷과 함께 골라지고(캔버스 그림 손잡이는 숨김), Delete로 그것만 지움(컷은 그대로), Ctrl+Z로 되돌림.

## 98. 배경 · 효과선 · 이미지 소재 편집 카드, 왼쪽 도구에 말풍선 복귀

- 레이어 패널에서 배경 / 집중선·속도선 / 이미지 소재 줄을 고르면 말풍선·효과음과 같은 자리(오른쪽 편집 카드)에 고칠 수 있는 버튼이 나온다.
  - 효과선: 종류(집중선↔속도선), 색, 밀도(12–90), 중심/방향 다시 찍기, 지우기.
  - 배경: 배경색(없애기), 전환 질감 프리셋, 배경 이미지 + 진하기, 모두 지우기.
  - 이미지 소재: 빼기, 속성 서랍 열기.
- 모든 변경은 Ctrl+Z로 되돌린다. Esc·×로 선택을 푼다.
- 말풍선은 다시 왼쪽 도구(B)에도 둔다. 에셋 패널에서도 그대로 넣을 수 있다(두 경로).

## 99. 편집 ↔ 씬 화면 연동

- 편집에서 식자·컷·씬을 지우거나 고친 뒤 씬 화면으로 돌아오면, 씬 화면이 예전 글을 그대로 보여 주던 문제를 고쳤다(원고 데이터는 바뀌었지만 컷 목록을 다시 그리지 않았음).

  - 엔진: 고른 기준의 샷 중앙값 × (엔진 길이/묶음 중앙)^0.7, 그 샷 10~90% 안으로. 글에 적은 {길이}는 그대로 우선
  - 콘티 머리 '컷 비율 기준'(상용 평균 기본 · 작품별 · 엔진 그대로). 대사 많은 8컷 예시 중앙: 엔진 1.23 → 평균 1.17 / 이두나! 0.66 / 호수의 백조 1.52

## 124. #소품 고정 문법(2026-11-26)
요청: 소품도 한 번 등장하면 형태가 고정돼야 함 → 인물 `@이름`처럼 소품 전용 문법을 따로 둠.
- 문법: `#이름` = 그림에 나오는 소품. 처음 나오는 컷에서 `#이름(색·재질·모양)`으로 형태를 적으면 그 형태로 고정. 이후 컷은 `#이름`만(조사는 붙여 써도 됨: `#회중시계를`, `#반지가`).
  - 엔진 `RE.props(text)` · `RE.stripProps(text)`: 컷 글에서 소품을 읽고, 행동 글에서는 `#`·괄호 형태를 지워 판정·검색에 영향 없게. 패널에 `props:[{name,look}]`
  - 조사 떼기: 설정집 이름을 먼저 맞추고(`RE.PROP_NAMES`), 없으면 받침 규칙(받침 뒤 은·을·과, 받침 없는 말 뒤 가·는·를·와)과 여러 글자 조사만. '이'는 목걸이·종이처럼 이름 끝일 때가 많아 같은 글에 조사 없는 표기가 있을 때만 뗌
- 고정: 소품은 세계관 '물건' 항목으로 등록(`ensureProps`). 괄호 형태가 있으면 입력하는 대로, 괄호 없는 `#이름`은 입력칸을 벗어날 때·씬/콘티 화면으로 갈 때·컷 프롬프트를 만들 때 등록. 이미 있는 항목의 형태는 바꾸지 않음(설정집이 이김), 컷 글에 다른 형태를 적으면 컷 아래에 "설정집과 달라요" 경고만
  - 세계관 물건 카드: 설명 칸이 "형태 (고정)"으로 바뀌고 `#소품에서 등록` 표시
- 프롬프트: NovelAI 컷 프롬프트에 그 물건의 태그를 구도 태그 바로 뒤에 그대로(모든 컷 같은 단어). 태그가 비어 있으면 컷 프롬프트 생성 때 Claude가 형태를 보고 한 번 지어 응답 `props`로 돌려주고, 설정집에 저장해 그 뒤 모든 컷·씬에 같은 태그(이미 태그가 있는 소품은 Claude가 바꾸지 않음). Claude 응답의 base가 어떻든 규칙 초안(태그 포함)이 합쳐져 소품 태그는 빠지지 않음
  - 자연어 프롬프트(`prompt.js`)에도 "■ 소품 (모양 고정)" 칸
- 화면: 씬 입력칸 `#이름` 강조, 툴바 `#소품` 넣기 버튼, 컷 아래 `◆이름 고정`, 콘티 카드 `◆이름` 칩(태그 미정이면 점선), 구성 컷 초안에서도 ◆ 표시. 구성 생성 프롬프트(grammar.js PROMPT)에도 문법 안내
- 테스트: e2e「#소품: 처음 적은 형태로 세계관에 고정 → 콘티 모든 컷에 같은 태그」

## 125. 요소별 레이어로 뽑기(2026-11-26)
요청: 배경과 인물을 따로 만들어 레이어로 고정 → 컷마다 요소별 이미지를 각각 뽑게.
- 콘티 위 「요소별 레이어로 뽑기」를 켜면 컷 카드가 컷 한 장 프롬프트 대신 레이어 줄로 바뀜(위→아래 순서: 소품 · 인물 · 배경). 줄마다 그림 칸 + 프롬프트 복사, 왼쪽에 겹친 미리보기
- 프롬프트(`RoughNAI.layers(o,p)`, 컷 프롬프트(Claude가 다듬은 것 포함)에서 나눔)
  - 배경: `no humans, scenery` + 장소·빛·앵글·분위기·세계관·화풍, 인물·소품 태그(소품 이름에서 나온 물건 태그 포함)는 뺌. 크기는 컷 크기
  - 인물: 그 인물의 컷 프롬프트(외형·표정·자세) + 샷 프레이밍·앵글 + `simple background, white background`. 크기는 샷별 세로 비율(클로즈업 1:1, 중경 1.25, 전신 1.7…), 위치는 NovelAI 캐릭터 칸 좌표, 폭은 샷별(클로즈업 95%, 중경 62%, 원경 18~26%, 두 명 이상이면 ×0.75)
  - 소품: `no humans, still life, object focus` + 설정집 소품 태그 + 흰 배경. 1024×1024
- 고정(같이 쓰기): 배경은 같은 씬에서 장소 태그와 앵글이 같은 컷끼리 한 장(키 `장소|앵글`, 장소를 못 읽거나 효과 배경이면 그 컷만), 소품은 한 장을 모든 씬의 그 소품 컷이, 인물은 컷마다(자세·표정이 달라서. 외형은 같은 태그)
- 그림 넣기: 배경은 컷 그림 자리(IMG.cut, `layerBg`=키)에 넣고 같은 키 컷에 복사. 인물·소품은 「흰 배경 지우기」(기본 켬: 테두리와 이어진 밝고 채도 낮은 픽셀만 투명, 경계 반투명)를 거친 PNG를 이미지 소재로 등록하고 컷 소재 목록(`pageEdits[slot].overlays`, `layer`·`key`)에 자동 추가 → 편집 화면 이미지 패널에서 위치·크기·회전·투명도를 옮김. 같은 레이어에 새 그림을 넣으면 위치는 그대로 두고 그림만 바뀜
  - 편집 화면에 들어갈 때 모든 씬을 맞춤(다른 씬의 같은 소품도 같은 그림)
- 내보내기: PSD 레이어 이름 `배경` / `인물 에드가` / `소품 회중시계`(예전 이름은 그림·이미지 소재 N), SVG id도 같은 이름
- 테스트: e2e「요소별 레이어: 배경·인물·소품 프롬프트 따로 → 넣은 그림이 편집 레이어로」

## 126. 인물 레이어도 같은 자세면 재사용(2026-11-26)
- 인물 레이어에 자세 키(`pose`): 화풍·흰 배경 지시를 뺀 그 인물 태그(외형·표정·자세·프레이밍·앵글)를 정렬해 이은 값. 키가 같으면 씬·컷이 달라도 같은 그림 하나를 같이 씀(넣으면 같은 자세 컷 모두에 들어감, 위치·크기는 컷마다 따로)
  - 표정이 다르면(예: 평온 ↔ 놀람) 다른 그림으로 봄. 자세 키가 없던 예전 인물 그림은 그 컷에서만
- 자세가 다른 컷: 레이어 줄의 「다른 컷 그림 쓰기…」에서 같은 인물의 다른 그림을 골라 이 자세로도 등록
- 레이어 줄에 "같은 자세 n컷이 같이 씀" 표시

## 128. 레이어 분리 고침: 소품이 모든 컷에 들어감 · 인물 레이어가 안 생김(2026-11-26)
- 원인 1(소품): Claude 지시문의 "이 씬의 모든 컷에 그 태그를 똑같이 쓴다"를 모든 컷에 넣으라는 뜻으로 읽을 수 있었음 + 세계관 물건을 키워드 부분 일치(`loreHits`)로 찾아 '책'이 '책상'에, 흔한 키워드가 엉뚱한 컷에 붙음
  - 지시문: "그 컷 props에 이름이 있는 컷에만, 없는 컷에는 넣지 않는다"
  - 컷의 소품 = `#`으로 적은 것 + 물건 '이름'이 낱말로 나온 것(이름 뒤 조사만 허용, 키워드는 안 씀)
  - `stripForeignProps`: 컷에 없는 소품의 태그를 그 컷 기본·인물 프롬프트에서 뺌(같은 태그 + 첫 태그의 사물 이름 부분을 품은 태그: gold pocket watch → "pocket watch"가 든 태그). 레이어 배경 프롬프트도 같은 규칙으로 그 컷 소품을 뺌
  - 레이어 맞추기(`syncLayers`)에서 컷 글에 더는 없는 소품·인물 레이어는 뺌(직접 넣은 소재는 그대로) → 예전에 잘못 붙은 소품도 정리됨
- 원인 2(인물): 소품·손·화면 같은 사물 중심 컷은 컷 프롬프트에서 인물 칸을 비우는 규칙이라 레이어에도 인물이 없었음 → 레이어용 인물(`layerCast`)은 구도와 상관없이 컷에 보이는 인물마다 만듦(외형·표정·자세, Claude가 다듬은 인물 묘사가 있으면 그것)
- 테스트: e2e「레이어: 소품은 나온 컷에만 · 소품 중심 컷에도 인물 레이어」

## 129. 레이어 구성 다시: 소품은 녹여 넣기 · 함께 나오는 인물 장면 · 배경은 늘 따로(2026-11-26)
요청: 소품은 따로 한 장보다 배경·인물에 녹아드는 경우가 많고, 인물은 둘이 상호작용하는 경우가 많아 각자 묘사와 함께 있는 장면이 모두 필요. 배경은 늘 따로여도 됨.
- 소품(컷마다 `pageEdits[slot].propAttach[이름]`, 레이어 줄의 고르기 상자)
  - 자동: 소품 이름 바로 뒤에 다루는 동사(들·쥐·꺼내·건네·잡·품·끼·흔들… 활용형 포함)가 있으면 그 컷 주인공(없으면 소품 앞에 가장 가까이 나온 인물) 레이어에, 아니면 배경에 녹여 넣음. 들고 쥐는 동작이면 `holding`도
  - 「○○에게」 「배경에」 「따로 레이어」로 직접 고름. 따로 레이어만 소품 한 장(모든 씬이 같이 씀)을 뽑음
  - 녹여 넣은 소품은 그 레이어 프롬프트에 설정집 태그 그대로(모양 고정), 다른 레이어에서는 뺌. 소품을 든 인물은 자세 키에 소품이 들어가 소품 없는 같은 자세와 다른 그림
- 함께(두 명 이상 보이는 컷): NovelAI V4.5 여러 인물 형식 — 기본 프롬프트(인원 1girl, 1boy + 상호작용 hug·holding hands·kiss·face-to-face·giving·pushing… + 샷·앵글 + 흰 배경) + 인물 칸마다 그 인물 묘사(위치 칸). 개별 인물 레이어도 그대로 두고, 개별 레이어에서는 상호작용 태그를 뺌
  - 함께 그림을 넣으면 그 컷은 개별 인물 대신 함께 그림 한 장(개별 레이어는 다시 쓰려면 함께 그림을 빼면 됨). 같은 자세(인원·상호작용·각 묘사가 같은) 컷끼리 재사용, 「다른 컷 그림 쓰기」도 됨
- 배경: 늘 따로. 배경에 녹인 소품이 있으면 같이 쓰는 키에 소품도 넣음(소품 있는 배경과 없는 배경을 구분)
- 테스트: e2e「요소별 레이어」(녹여 넣기 → 배경에 → 따로 레이어 전환),「두 인물이 함께 나오면 각자 + 함께 레이어」

## 130. 레이어 그림 흰색 자동 투명(2026-11-26)
- 「흰색 자동 투명」(콘티, 기본 켬, 예전 이름 '흰 배경 지우기'): 인물·함께·소품 레이어 그림을 넣을 때
  1) 테두리와 이어진 거의 흰색(밝고 무채색) 배경 → 투명
  2) 완전 흰색(RGB 모두 250 이상·무채색) 덩어리는 테두리와 떨어져 있어도 투명 — 팔과 몸 사이, 두 인물 사이 빈틈
  3) 아주 작은 완전 흰 덩어리(그림 넓이의 0.05% 또는 60픽셀 미만: 눈 하이라이트·반사광)는 남김, 연한 색(크림·회색 옷)은 남김

배경: NovelAI는 캐릭터 얼굴·옷·화풍 고정은 잘하지만 상황(두 사람의 상호작용, 큰 동작, 소품 사용, 공간 배치) 표현이 약함. GPT 이미지는 상황·구도는 잘 잡지만 캐릭터가 컷마다 달라짐 → 역할을 나눔: **GPT = 구도·연기, NovelAI = 인물 일관성·화풍**

### 1. 컷마다 생성 경로를 고름(자동 + 직접 바꾸기)
| 경로 | 쓰는 컷 | 근거(규칙이 이미 아는 값) |
|---|---|---|
| NovelAI 바로 | 인물 1명 · 클로즈업/중경 · 감정 표정 중심 | `mode=character`, 인물 1명, 큰 동작·위치 관계 없음 |
| GPT 구도 → NovelAI 다시 그리기 | 2명 이상 상호작용 · 큰 동작 · 소품을 쓰는 동작 · 원경 인물 + 장소 | 인물 2명+, `read.spatial`, `dynamic pose`·running 등, 보이는 소품, `mode=distant` |
| GPT만 | 배경·소품·효과 컷(인물 없음) | `mode=scenery/object/effect` |
| NovelAI만(배경 포함) | 작가가 고른 경우 | 컷 수정에서 지정 |
- 컷 카드에 경로 칩(예: 「GPT→NAI · 두 사람이 닿는 동작」), 눌러서 바꿈. 컷 글 `{경로:GPT}` 지시로도

### 2. 컷 카드 = 단계 3칸
1. **구도(GPT)**: 자연어 프롬프트(화면 구성 → 인물 위치 왼쪽/오른쪽 → 동작 → 소품 → 배경 → 빛·분위기 → 카메라, 끝에 "글자·말풍선 없이", 칸 비율). 인물은 짧은 식별 문구(머리색·옷)만 — 얼굴은 다음 단계에서 덮음. 캐릭터 시트 그림을 같이 붙이라는 안내 + 시트 복사 버튼. 결과 그림 넣는 칸
2. **인물 다시 그리기(NovelAI img2img)**: 지금의 NAI 태그 + 1단계 그림을 Base Image로 · 세기(strength) 추천값(구도 유지 0.5~0.6, 얼굴만 0.4 + 인페인트) · Character Reference · Vibe. 결과 그림 넣는 칸
3. **최종**: 두 그림 나란히, 하나 고르기(편집 화면은 고른 그림을 씀). 컷마다 그림 여러 장 보관(버전)
- 경로가 「NovelAI 바로」면 1칸만, 「GPT만」이면 1·3칸만

### 3. 프롬프트 생성(Claude 한 번에 두 형식)
- 같은 사실(누가·무엇을·어디서·어떤 구도)로 GPT 자연어와 NAI 태그를 함께 만듦 → 두 단계가 서로 어긋나지 않게. 응답 스키마에 컷마다 `gpt` 추가
- 규칙 초안은 `rough/prompt.js` 자연어(natural) 형식을 이 페이지에 연결 + 지금의 절 해석(누가·안 한 동작·위치 관계)·DB 원본 컷 구도를 자연어로
- GPT 쪽은 "하지 않은 동작은 그리지 않는다", "인물 수·좌우 위치 고정"을 문장으로 명시(GPT는 태그 가중치가 없어서 문장 순서·명시가 중요)

### 4. 캐릭터 시트(두 모델을 잇는 고리)
- 설정집 인물마다 NovelAI로 뽑은 시트(정면·전신·표정 몇 장)를 보관 → GPT에 참고 그림으로, NovelAI에 Character Reference로 같은 그림을 씀
- 시트가 없으면 콘티 머리에 「캐릭터 시트 먼저」 안내 + 시트용 NAI 프롬프트(흰 배경·전신·정면/옆/뒤)

### 5. 씬 단위로 빠르게
- 씬의 GPT 프롬프트 전부 복사/저장(컷 번호 붙여), 그림 여러 장을 한 번에 넣으면 파일 이름·순서로 컷에 배정
- 레이어 모드와 합치기: 배경·함께 레이어는 GPT, 인물 단독 레이어는 NovelAI

### 6. 단계별 진행안
- 1단계(손으로, 키 없이): 경로 자동 고르기 · 단계 3칸 · GPT 자연어 프롬프트 · 그림 버전·최종 고르기 · 씬 일괄 복사/넣기 · img2img 세기 안내
- 2단계: Claude가 GPT+NAI를 함께 생성 · 캐릭터 시트 · 레이어 모드 연결
- 3단계(선택): OpenAI 이미지 API·NovelAI API로 툴에서 바로 생성, GPT 결과를 NAI img2img에 자동으로 넘김, Claude가 그림을 보고 "컷 글과 맞는지" 확인
