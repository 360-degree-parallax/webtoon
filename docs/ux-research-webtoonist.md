# 웹툰 작가 관점 UX 조사: 유저플로우 · 가독성 · 제작 실용성 (2026-11-23)

포스타입을 UX 기준으로 삼고 있는 지금, ROUGH가 **실제로 한 화를 만드는 작가**에게 어떻게 쓰이는지를 세 방향에서 조사했다.

1. 포스타입의 구조와 화면 원칙(공개 글·공지·도움말 검색 결과)
2. 웹툰 제작 현장 자료(작가 인터뷰·기사·논문, 플랫폼 규격, 식자 가이드, 클립스튜디오 웹툰 기능)
3. 우리 툴 실측(Playwright로 6개 화면 × 데스크톱 1440×900 · 휴대폰 390폭, 기본 예시 원고 2씬 12컷)

## 0. 결론 먼저

- **잘 되어 있는 것:** 글 → 연출 자동 → 그림 넣기 → 식자 편집 → 연재용 분할·PSD까지 한 줄로 이어진다. 읽기 모드(360·390·430), 씬 길이 통계("세로 약 6,058px · 휴대폰 5화면"), 「· 자동」 표시, 모든 화면 실행 취소는 작가가 실제로 필요한 것과 맞는다.
- **가장 큰 구멍은 화면이 아니라 구조다.** 주간 연재는 "작품 → 회차 → 씬"인데 툴은 "브라우저 하나 = 원고 하나"다. 포스타입이 채널 → 시리즈 → 포스트로 푸는 부분이 비어 있다.
- **분량이 현장과 다르다.** 현장 한 화는 60~70컷인데, 우리가 확인한 건 12컷이다. 12컷 편집 화면이 이미 세로 19,176px(화면 11.9장)이라, 70컷이면 약 11만 px가 된다. 이 규모에서 편집 화면·레이어 목록·내보내기가 버티는지는 **아직 시험하지 않았다.**
- **휴대폰에서는 첫 화면에 작품이 안 보인다.** 씬 화면 첫 컷 글이 화면 높이 688 중 605px에서 시작한다.
- **식자 기본 크기가 작은 쪽 끝에 있다.** 대사 21px·나레이션 19px(690폭 기준)은 390폭 휴대폰에서 11.9px·10.7px로 보인다.

## 1. 조사 방법과 한계

| 대상 | 본 것 | 못 본 것 |
|---|---|---|
| 포스타입 | 공개 글 화면(이전 측정, docs/readability-vs-postype.md), 에디터 개선 공지(2024-12), 크리에이터 가이드 시리즈 목록, **도움말 센터 본문 13개**(에디터 사용법·발행·이미지·유료·공개 대상·시리즈·저장과 복원·용량 등, §2-1) | 에디터를 **직접 써 보는 것**(로그인 필요). 화면은 도움말 속 공식 캡처 4장으로 확인(§2-2) |
| 제작 현장 | 작가 인터뷰·기사 3건, 학회 논문 1건, 클립스튜디오 공식 안내, WEBTOON 크리에이터 핸드북 요약, 작가 커뮤니티 글 | 작가를 직접 인터뷰하지 않음. 자료 다수가 2017~2021년 것 |
| 우리 툴 | 화면별 조작 요소 수, 40px 미만 조작 요소, 글자 크기 분포, 첫 화면에서 작품이 나오는 위치, 식자 실제 크기 | 사람이 쓰는 시간, 70컷 규모 성능 |

수치 중 "작가는 이렇게 느낀다"는 부분은 자료에 근거한 추정이다. 사람 확인(5명 안팎)은 여전히 남은 일이다.

## 2. 포스타입에서 가져올 원칙

포스타입은 제작 툴이 아니라 발행 플랫폼이다. 그래서 화면 생김새보다 **정보를 어디에 두는지**를 봤다.

| 원칙 | 포스타입 | 우리 |
|---|---|---|
| 작품 구조 | 채널 → 시리즈(총 36화처럼 회차 목록) → 포스트 | 원고 하나. 회차·작품 목록 없음 |
| 쓰는 화면 | 본문이 주인공. 넣을 것은 [+] 하나로(이미지·버튼·공개 상자) | 씬 화면은 비슷함(컷 글 18px, 문법 버튼 한 줄). 편집 화면은 첫 화면에 조작 요소 89개 |
| 설정 위치 | 공개 범위·가격·댓글 권한·대표 이미지·예약은 전부 [발행] 한 곳 | 내보내기 메뉴 한 곳(좋음). 다만 '올리기 전 점검'은 따로 흩어져 있음 |
| 나중에 올리기 | 예약 발행, 발행대기 목록 | 해당 없음(발행 기능 없음) |
| 읽는 화면 | 시리즈명 → 제목 → 본문 고정 폭(18px/1.75) → 이전·다음 화 | 읽기 모드에 제목만. 씬 이동·다음 화 없음 |
| 유료 경계 | '공개 상자' 한 줄로 무료/유료 구간을 본문 안에서 나눔 | 해당 없음. 단, 같은 방식으로 **"미리보기는 여기까지" 선**을 원고에 둘 수 있음(§6-P2) |

가져올 것은 세 가지다. ① 작품·회차 구조, ② 넣을 것을 한 입구로 모으기, ③ 내보내기 직전 설정·점검을 한 화면으로.

### 2-1. 도움말 본문으로 확인한 것 (보완)

도움말 센터 본문을 읽고 위 표를 확인·보완했다. 웹툰 작가에게 직접 닿는 것만 추렸다.

**포스타입에 웹툰을 올리는 실제 규격**
| 항목 | 포스타입 | 우리 내보내기에 주는 뜻 |
|---|---|---|
| 웹툰용 이미지 묶음 | 이미지 레이아웃 5종 중 **「끊김 없는 이미지(웹툰)」**: 여러 장을 세로로 틈 없이 이어 붙임 | 연재용 분할 파일을 그대로 올리면 됨. 컷 사이 여백에서 자르는 지금 방식과 맞음 |
| 보이는 폭 | 본문 너비 **최대 700px**. 작은 이미지는 본문 너비로 확대 | 690px 기준 원고가 거의 그대로 보임 |
| 올릴 수 있는 크기 | PNG·JPG 한 장 가로·세로 **10,000px 미만, 50MB 이하, 포스트당 100장**. 스트리밍은 가로 1,600px까지 | 한 장 높이를 10,000px 아래로. 70컷(약 11만 px)이면 12장 이상 → 100장 한도 안 |
| 권장 | 그림은 PNG, 화질이 떨어지면 72dpi·가로 1,000px 안팎 | 포스타입용은 1,000px 폭 PNG 선택지가 있으면 좋음 |
| 이미지 넣기 | 보관함 올리기 · 끌어다 놓기 · Ctrl+V 붙여넣기. 묶음 안 순서는 위·아래 화살표 | 콘티 화면의 그림 넣기(클릭·끌기·붙여넣기)와 같은 세 가지 |

→ 분할 내보내기에 **「포스타입」 프리셋(폭 690 또는 1,000 · 한 장 10,000px 미만 · PNG)** 을 넣을 근거가 생겼다. 네이버·카카오와 달리 공식 문서로 확인한 수치다.

**에디터 구조**
- 넣을 것은 「삽입」 한 묶음: 공개 상자·이미지·파일·투표·외부 링크·코드·버튼. 왼쪽의 빠른 삽입(+)으로도 넣는다.
- 저장: Ctrl+S 수동 저장 + **5분 자동 저장(켜야 함)** + 편집 이력(포스트당 최근 10개, 60일). 저장하지 않고 나가면 사라진다.
  - 우리는 자동 저장이 늘 켜져 있고 기록을 10분마다 30개 남긴다. 이 부분은 포스타입보다 안전하다. 다만 **Ctrl+S가 없다.** 작가 손버릇이라 "저장됨"을 한 번 보여 주는 것만으로도 안심이 된다.
- 단축키 도움말은 오른쪽 위 '?' — 우리와 같다. 실행 취소 Ctrl+Z, 다시 실행 Ctrl+Shift+Z도 같다.
- 블록 위·아래 이동 Ctrl+Shift+↑/↓ — 우리 컷 순서 바꾸기에 같은 키를 주면 익숙하다.
- 맞춤법 검사가 에디터 안에 있다(전체 또는 선택 영역). 우리 「대사 교정」에 해당.
- 미리보기는 "발행 후 화면"을 그대로 보여 준다. 우리 읽기 모드에 해당.

**발행 패널에 모인 것(한 곳)**
대표 이미지 · 시리즈 · 태그 · 가격 · 익명 구매/후원 · 공개 설정 · 성인 표시 · 발행 시각 · 댓글 권한 · 소장본 열람 기간 · 공지. 휴대폰에서는 에디터 아래 '발행 옵션'으로 열린다.
→ §6-6 "올리기 전 점검 한 화면"의 모양을 이대로 따르면 된다: 내보내기를 누르면 **한 패널에 점검 + 설정 + 내보내기**.

**시리즈(작품)와 회차**
- 시리즈 = 여러 포스트를 한 작품으로 묶는 것. 표지·제목·설명·태그. 채널당 1,000개.
- 포스트 여러 개를 골라 한 번에 다른 시리즈로 옮길 수 있다. 시리즈를 지워도 포스트는 남는다.
- **약점:** 회차 순서는 발행 순서뿐이라, 바꾸려면 아래에 둘 것부터 하나씩 '지금'으로 재발행해야 한다.
→ §6-1 회차 목록을 만들 때 가져올 것: 표지·제목·설명, 회차를 작품 사이로 옮기기, 작품을 지워도 회차는 남기기. 피할 것: 순서 바꾸기가 번거로운 구조 → 우리는 끌어서 순서 바꾸기.

**공개 상자(미리보기 경계)**
- 본문 안의 선 하나. 위는 미리보기, 아래는 유료·구독자·멤버십 전용. 끌어서 옮기거나 단축키로 넣는다.
- 가격은 100~500,000포인트, 10 단위.
→ §6-12 "미리보기는 여기까지" 선을 원고에 두면, 작가가 **컷 호흡을 보면서 끊는 자리**를 정할 수 있다. 포스타입에 올릴 때 그 자리에 공개 상자를 두면 된다.

### 2-2. 에디터 화면 (도움말 속 공식 캡처 4장으로 확인)

로그인 없이 볼 수 있는 공식 캡처를 찾았다: 데스크톱 에디터 1장, 휴대폰 에디터 2장(이미지 선택 상태), 발행 패널 2장(데스크톱·휴대폰). 실제 화면을 잰 것이 아니라 캡처를 본 것이라 px 수치는 대략이다.

**데스크톱 에디터**
- 위가 **두 줄뿐**이다.
  - 1줄: 왼쪽 ← 뒤로 / 오른쪽 `0자` · `···` · `?` · **저장**(연한 회색) · **발행**(검정).
  - 2줄: 가운데 정렬 도구 한 줄, 아이콘만 약 20개. `+` · 실행 취소 · 다시 실행 | 제목 종류 · 글꼴 | 굵게·기울임·밑줄·취소선·글자색 | 링크·이미지·인용·구분선 | 정렬·목록·들여쓰기 | 기본 스타일 · 맞춤법.
- 본문은 가운데 한 기둥(화면 폭의 약 60%). 제목(큰 회색 안내 글) → 부제목 → 가는 선 → 내용. **옆 패널이 하나도 없다.**
- 공개 상자는 본문 안의 카드 한 장("상자를 옮겨 공개 분량을 설정해 보세요" + 끌기 손잡이).
- 오른쪽 아래에 떠 있는 동그란 버튼 하나(기기 미리보기).
- 검정 버튼은 화면에 **발행 하나뿐**이다.

**휴대폰 에디터**
- 1줄은 그대로(← · 0자 · ··· · 저장 · 발행). 2줄 도구는 9개로 줄인다(링크·이미지·인용·구분선 | 정렬·목록 | 기본 스타일·맞춤법). 굵게·글자색 같은 건 뺀다.
- 이미지를 누르면 **그 이미지 바로 위에 작은 도구 묶음**이 뜬다: 위로·아래로 | 너비 2종 | 편집 | 지우기. 이미지 아래에는 "여기에 줄 넣기" 동그란 버튼.
- 즉, 고른 것에 대한 조작은 화면 위 막대가 아니라 **고른 것 옆**에 나온다.

**발행 패널**
- 한 기둥. 항목마다 이름(굵게) + 개수(`대표 이미지 0/20`, `태그 0/5`) → 입력 → **회색 도움말 한두 줄**.
- 순서: 대표 이미지 → 시리즈(고르기 + 「시리즈 추가」) → 태그 → 공개 설정(라디오 5개) → 가격 → … → 발행 시각(지금/예약).
- 맨 아래 오른쪽에 취소 · **발행하기**(파랑).
- 공개 설정 아래에 "공개 분량을 설정하고 싶다면 에디터의 공개 상자 위치를 옮겨 보세요"처럼 **다른 화면에서 할 일을 그 자리에서 알려 준다.**

**우리 화면과 견주면**

| | 포스타입 에디터 | 우리 씬 화면 | 우리 편집 화면 |
|---|---|---|---|
| 본문 위 줄 수 | 2줄 | 3줄(머리 · 단계 탭 · 씬 막대) | 4줄(머리 · 단계 탭 · 편집 막대 · 상황 막대) |
| 검정(주) 버튼 | 발행 1개 | **2개**(내보내기 · 콘티 보기) | 1개(내보내기) |
| 옆 패널 | 없음 | 왼쪽 씬 목록 + 오른쪽 미리보기 | 도구 막대 + 레이어 + 에셋 |
| 고른 것 조작 | 고른 것 바로 위 작은 도구 묶음 | 컷 카드 안 | 위쪽 상황 막대 + 오른쪽 패널 |
| 상태 표시 | 오른쪽 위 `0자` | 왼쪽 위 "자동 저장", 통계는 본문 안 | 왼쪽 위 "자동 저장" |
| 휴대폰 도구 | 9개로 줄임 | 문법 버튼 6개(비슷함) | 가로 스크롤 |

우리 화면은 원고·연출·식자를 한꺼번에 다루는 제작 툴이라 포스타입처럼 패널을 다 없앨 수는 없다. 그래도 그대로 가져올 수 있는 것이 다섯 가지다.

1. **검정 버튼은 화면에 하나.** 씬 화면의 「콘티 보기」를 테두리 버튼으로 낮추고 검정은 「내보내기」만.
2. **휴대폰 편집: 고른 것 옆에 작은 도구 묶음.** 컷을 누르면 컷 위에 위로·아래로 | 그림 편집 | 간격 | 지우기. 말풍선을 누르면 고치기 | 모양 | 크기 | 지우기. 지금은 위쪽 상황 막대를 가로로 밀어야 한다.
3. **오른쪽 위 상태 한 칸.** 포스타입의 `0자` 자리에 `12컷 · 휴대폰 9화면`처럼 분량을. 작가가 가장 자주 확인하는 숫자다.
4. **내보내기를 발행 패널 모양으로.** 한 기둥, 항목 이름 + 개수 + 회색 도움말, 맨 아래 주 버튼. 점검 결과("빈 컷 3개")도 같은 패널 위쪽에.
5. **씬 화면 위 줄 수 줄이기.** 단계 탭과 씬 막대를 한 줄로 합치는 안(왼쪽 단계, 가운데 문법 버튼). 첫 컷이 400px → 약 340px로 올라온다.

## 3. 웹툰 작가는 실제로 어떻게 일하나

**분량과 시간**
- 주간 연재 한 화는 컬러 60~70컷이 업계 표준처럼 통한다(이투데이·오마이뉴스 인터뷰). 논문은 "1회 40~80컷 이상"으로 정리한다.
- 한 작가는 **스토리와 콘티에 각각 이틀**, 가장 오래 걸리는 단계로 꼽았다. 그림은 보조 작가가 돕지만 스토리·콘티는 혼자 한다.
- 컷 하나에 밑그림·채색·효과·말풍선이 반복돼 컷당 1시간 안팎.

→ ROUGH가 줄여 줄 수 있는 시간은 **스토리·콘티의 나흘**이다. 그림 단계가 아니라 여기가 승부처다.

**분업과 넘기기**
- 콘티는 글 작가·그림 작가·채색·담당자가 소통하는 문서다(웹툰가이드). 즉 혼자 보는 메모가 아니라 **남에게 넘기는 결과물**이다.
- 클립스튜디오 쪽 흐름: 콘티를 반투명으로 깔고 → 칸 → 선화 → 채색 → 말풍선/효과음 레이어 → 웹툰 내보내기(분할). 레이어 이름을 "콘티 / 글자·말풍선 / 효과음"으로 두는 템플릿이 흔하다.

→ 우리 PSD(컷 폴더·칸 마스크·식자 레이어 + 대사 목록)는 이 흐름과 맞는다. 빠진 것은 **담당자·그림 작가에게 보여 줄 검토용 콘티**다.

**규격**
- 네이버 690px, 카카오페이지 720px은 **올리는 폭**일 뿐이고, 작업은 보통 1,500~2,500px에서 한다(작가 계정 글, 2021).
- 도전만화는 파일당 5MB·전체 50MB·jpg/gif라는 정리가 있다(오래된 자료, 올리기 전 공식 안내 확인 필요).

**식자와 호흡**
- WEBTOON 핸드북: 칸당 말풍선 3개 이하, 풍선당 1~2문장, **반드시 휴대폰으로 확인**. 글자 크기는 폭에 따라 달라 고정 규칙은 없다.
- 세로 스크롤에서는 독자의 스크롤 속도가 곧 연출 속도이고, 컷 사이 여백이 연출 수단이다(논문·클립스튜디오 안내).
- 우리 레퍼런스 분석(docs/lettering-analysis.md): 실제 연재작 대사는 690폭에서 21~26px, 컷 사이 여백 100~350px.

|---|---|---|---|---|---|
| 캐릭터 | 27 / 14 | 4 | 13px | 0% | 1.9장 |
| 세계관 | 39 / 9 | 0 | 13px | 0% | 2.2장 |
| 구성 | 15 / 10 | 5 | 13px | 0% | 1.0장 |
| 씬 | 46 / 31 | 23 | **18px** | 1% | 1.7장 |
| 콘티 | 34 / 14 | 13 | 15px | 5% | 4.1장 |
| 편집 | **97 / 89** | **81** | 13px | 9% | **11.9장** |
| 씬 (휴대폰) | 46 / 18 | 14 | 18px | 1% | 3.4장 |
| 콘티 (휴대폰) | 34 / 12 | 11 | 15px | 4% | 8.6장 |
| 편집 (휴대폰) | 36 / 10 | 6 | 13px | 13% | 9.0장 |

- 첫 화면에서 작품이 나오는 위치: 씬 첫 컷 글 400/900(데스크톱), **605/688(휴대폰)**. 콘티 첫 그림 칸 563/900, **587/688(휴대폰)**. 편집 첫 컷 441/900.
- 식자: 대사 21px, 나레이션 19px(690폭). 읽기 모드 390폭에서 배율 0.565 → **11.9px, 10.7px**.

- 캐릭터·세계관·구성의 "가장 많은 글자 13px"은 라벨·설명 글이 많아서다(입력값 자체는 더 큼).

## 5. 진단

### 5-1. 유저플로우

**흐름 자체는 현장 순서와 맞다.** 캐릭터 → 세계관 → 구성 → 씬 → 콘티 → 편집은 기획 → 글콘티 → 그림 → 식자 순서다. 열면 씬(글쓰기)에서 시작하는 것도 맞다. 작가는 설정을 다 채우고 쓰지 않는다.

문제는 다섯 가지다.

1. **회차가 없다.** 2화를 시작하려면 작업 파일을 저장하고 원고를 비워야 한다. 캐릭터는 보관함이 있어 이어 쓸 수 있지만, "지난 화 마지막 컷"을 보며 다음 화를 쓰는 흐름이 없다. 주간 연재에서 매주 겪는 일이다.
2. **'콘티'라는 이름이 작가의 말과 다르다.** 작가에게 콘티는 컷 배치를 거칠게 그린 것이다. 우리 콘티 화면은 프롬프트 복사 + 그림 넣기다. 실제 콘티(컷 길이·간격·말풍선 자리)는 씬 화면 오른쪽 미리보기와 편집 화면에 있다. 처음 온 작가는 5번 탭에서 콘티를 찾다가 프롬프트를 만난다.
3. **씬 6컷 단위 × 70컷.** 한 화가 씬 10여 개가 된다. 씬 사이를 오가는 수단이 위쪽 선택 상자와 왼쪽 목록뿐이라, "화 전체를 한눈에" 보는 곳이 편집 화면(세로 11만 px 예상)밖에 없다.
4. **넘기기용 콘티가 없다.** PNG 한 장은 있지만 컷 번호·지문·대사가 옆에 붙은 검토용 문서가 아니다. 담당자 피드백("23번 컷 대사 줄이자")을 받으려면 번호가 보여야 한다.
5. **올리기 직전 점검이 흩어져 있다.** 대사 교정, 완성본 점검, 분할 설정이 각각 다른 버튼이다. 포스타입은 이걸 [발행] 한 곳에 모은다.

### 5-2. 가독성

- 지난 정리로 화면 글자는 대부분 13px 이상이 됐다. 씬 화면 컷 글 18px은 포스타입 본문(18px)과 같다.
- **남은 것은 화면 글자가 아니라 결과물 글자다.** 대사 21px은 레퍼런스 범위(21~26px)의 가장 아래다. 독자의 휴대폰에서 11.9px이면 작은 편이고, 나레이션 10.7px은 더 작다. 툴 화면을 아무리 고쳐도 독자가 읽는 건 이 글자다.
- 편집 화면은 첫 화면 조작 요소 89개 중 81개가 40px 미만이다. 데스크톱 전문 툴로는 흔한 밀도지만, "작품이 먼저 보이게"라는 기준에서는 여전히 툴이 먼저 보인다.
- 휴대폰 읽기 모드 머리에서 작품 제목이 뒤쪽 위 막대와 겹쳐 보인다(390폭 캡처에서 확인).
- 휴대폰 씬 화면은 첫 화면의 88%를 위 막대·문법 버튼·씬 목록·통계가 차지한다.

### 5-3. 제작 실용성

| 작가가 하는 일 | 지금 | 평가 |
|---|---|---|
| 글콘티 쓰기 | 컷 카드, `{…}` 문법, 대사·식자·효과음 구분, 대사 자동 나누기 | 강점. 이틀 걸리는 단계를 직접 줄임 |
| 호흡 보기 | 컷 길이 막대, 간격 표시, 세로 px·휴대폰 화면 수, 읽기 모드 | 강점. "휴대폰으로 확인" 원칙과 일치 |
| 식자 | 말풍선 15종, 효과음 615종 × 4타입, 미리보기 타일 | 강점. 칸당 풍선 수·풍선당 글자 수 경고는 없음 |
| 그림 넣기 | 컷별 프롬프트·그림 첨부, 레퍼런스 컷 | 직접 그리는 작가에게는 "밑그림 받침"으로만 쓰임. 그 용도가 화면에 설명돼 있지 않음 |
| 그림 작가에게 넘기기 | PSD(컷 폴더·칸 마스크·식자 레이어) + 대사 목록 | 강점. 클립스튜디오 템플릿 관행과 맞음 |
| 올리기 | 연재용 분할(폭·높이·형식·품질) | 플랫폼 프리셋(690/720)과 파일 용량 경고가 없음 |
| 매주 반복 | 작업 파일 저장·불러오기, 자동 기록 30개 | 회차 관리 없음. 가장 큰 공백 |
| 작업 폭 | 690 기준 | 실제 작업은 1,500~2,500px. PSD를 2배 이상으로 내보내는 선택지가 필요한지 확인해야 함 |

## 6. 제안 (우선순위)

**P0 — 연재에 쓰려면 먼저**
1. **작품 → 회차 목록.** 위 막대 씬 선택 상자 왼쪽에 회차. 회차마다 원고 따로, 캐릭터·세계관·즐겨찾기·시퀀스는 작품 공통. 새 회차를 만들 때 "지난 화 마지막 씬 보기".
2. **70컷 시험 원고.** 60~70컷 픽스처를 만들어 편집 화면 그리기 시간, 레이어 목록, 분할·PSD 내보내기 시간을 잼. 느리면 화면에 보이는 씬만 그리기.
3. **식자 기본 크기.** 대사 기본 23~24px로 올릴지 결정(레퍼런스 중간값). 읽기 모드에 "휴대폰에서 11px 미만 글자 N개" 표시.
4. **휴대폰 씬 화면.** 씬 목록·통계를 접어 첫 컷 글이 첫 화면 위쪽에 오게. 읽기 모드 머리 겹침 수정.

**P0에 덧붙임 (작은 일, §2-2)**
4-1. 검정 버튼은 화면에 하나(씬 화면 「콘티 보기」 낮추기). 오른쪽 위에 분량 한 칸(`12컷 · 휴대폰 9화면`).
4-2. 휴대폰 편집: 고른 컷·말풍선 옆에 작은 도구 묶음.

**P1 — 현장 흐름에 맞추기**
5. **검토용 콘티 내보내기.** 컷 번호 + 컷 그림 + 지문·대사를 나란히 놓은 PDF/이미지. 담당자·그림 작가용.
6. **올리기 전 점검 한 화면.** 내보내기를 누르면 대사 교정 · 빈 컷 · 칸당 말풍선 3개 초과 · 풍선당 글자 수 · 작은 글자를 한 목록으로. 포스타입 [발행] 패널 방식.
7. **플랫폼 프리셋.** 분할 내보내기에 **「포스타입」(폭 690 또는 1,000 · 한 장 10,000px 미만 · PNG · 100장 이하, 공식 도움말로 확인)** 을 먼저 넣고, "네이버 690 · 카카오 720"은 공식 한도를 확인한 뒤 추가. 파일당 용량·장수 표시.
7-1. **Ctrl+S**: 누르면 "저장됨" 표시(자동 저장은 이미 됨). 컷 순서 바꾸기 Ctrl+Shift+↑/↓.
8. **5번 탭 이름.** '콘티'를 '그림'(또는 '작화')으로 바꾸고, 씬 화면 오른쪽 미리보기에 '콘티'라는 이름을 붙이는 안. 예전에 콘티·작화를 합친 결정과 닿아 있어서 결정이 필요함.
9. **화 전체 보기.** 씬 카드(제목·컷 수·세로 길이·하이라이트)를 한 줄로 늘어놓은 개요. 씬 순서 바꾸기도 여기서.

**P2 — 그다음**
10. 에셋 탭 4묶음 정리, 올리면 미리 적용(이미 기획한 3·4번).
11. PSD 배율 선택(1× / 2× / 3×).
12. "미리보기는 여기까지" 선: 무료 공개 구간을 원고에서 표시하고 그 지점까지만 분할 내보내기.
13. 편집 화면 휴대폰 조작 요소 44px.

## 7. 다음에 확인할 것

- 작가 3~5명에게 "1화 6컷 글을 주고 분할 파일까지" 과제를 주고 막힌 곳·시간 재기. 위 진단 중 2번(콘티 이름)과 4번(검토용 콘티)은 사람 확인 없이는 추정이다.
- 포스타입 에디터에 실제로 웹툰 이미지 묶음을 올려 보기(로그인 필요). 공식 캡처로 배치는 확인했지만 「끊김 없는 이미지(웹툰)」 고르는 화면과 글자 크기 실측은 아직.
- 네이버·카카오 최신 업로드 규격.
